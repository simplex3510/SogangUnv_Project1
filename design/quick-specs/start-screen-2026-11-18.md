# Quick Design Spec: 시작 화면

**Type**: New Small System
**Scope**: 게임 실행 직후 카메라를 차량 클로즈업 구도에 두고 우측에 사선 메뉴(시작·조작법·종료)를 띄운다. **시작**을 누르면 카메라가 인게임 구도로 이동하고 하루가 시작된다. 조작법 화면 본체, 일시정지 메뉴, 하루 종료 후 메인 메뉴 복귀, 설정 화면은 다루지 않는다.
**Date**: 2026-11-18
**Estimated Implementation**: 6~8시간
**Story**: `production/epics/over-load/story-028-start-screen.md` (조작법 화면은 후속 스토리 029)

## Overview

씬이 로드되면 하루 운영은 시작하지 않은 채 대기하고, 메뉴 전용 카메라가 플레이어 차량을 화면 왼쪽에 가득 채운다. 화면 오른쪽에는 메뉴 버튼 3개가 `\` 모양 사선으로 놓인다. **시작**을 누르면 메뉴가 사라지고, 카메라가 인게임 카메라로 부드럽게 전환된다. 전환이 끝나면 하루가 시작되고 조작이 풀린다.

## Core Rules

1. **상태**: `Menu → Starting → Playing` 세 단계다.
   - `Menu`: 씬 로드 직후 상태. 하루 시계와 물류 생성이 정지하고 플레이어 입력이 막힌다.
   - `Starting`: 시작 버튼을 누른 뒤 카메라가 전환되는 동안.
   - `Playing`: 전환이 끝난 뒤. 이 시점에 `StartDay()`를 호출하고 조작을 푼다.
2. **하루 시작 시점 변경**: `DailyOperationSystem.Start()`가 `StartDay()`를 자동 호출하지 않는다. 시작 화면이 `Playing`으로 넘어갈 때 호출한다. `Start()`의 `SetControlEnabled(false)`는 유지한다.
3. **카메라**: 시네머신 가상 카메라 `MenuCam`을 추가한다. 기본 인게임 가상 카메라보다 우선순위를 높게 두어 `Menu` 동안 `MenuCam`이 활성이다.
   - 구도: 사용자가 첨부한 사진(차량 정면 앞쪽 낮은 위치)처럼 차량이 화면 왼쪽에 가득 차게 한다.
   - 위치와 회전은 Editor에서 눈으로 맞추고 씬에 저장한다. 기준 사진과 비교한 스크린샷을 증거로 남긴다.
   - 시작을 누르면 `MenuCam` 우선순위를 내려, `CinemachineBrain`의 블렌드로 인게임 카메라로 돌아간다. 블렌드 시간은 설정값이다.
4. **메뉴 레이아웃**(UI Toolkit, 기존 HUD와 같은 `HudPanelSettings` 기준)
   - 버튼 3개를 위에서 아래로 시작 → 조작법 → 종료 순으로 놓는다.
   - 각 행을 아래로 갈수록 오른쪽으로 일정 간격 밀어서 `\` 모양 사선이 되게 한다. 행마다 `translate`의 X 값을 단계적으로 주는 방식이라 글자는 기울이지 않는다.
   - 메뉴 영역은 화면 오른쪽 약 45%이고, 차량이 있는 왼쪽 영역은 비워 둔다.
   - 메뉴가 떠 있는 동안 기존 HUD(속도계, 상태, 적재 패널 등)는 숨긴다. 시작 시 메뉴를 숨기고 HUD를 보인다.
5. **버튼 동작**
   - 시작: 규칙 1~3의 흐름을 실행한다. `Starting` 이후에는 중복 클릭을 무시한다.
   - 조작법: 이 스토리에서는 **비활성 상태**(흐린 표시)로 둔다. 후속 스토리에서 활성화한다. 연결 지점으로 `StartMenuUI.ControlsRequested` 이벤트를 선언만 해 둔다.
   - 종료: `GameManager`에 `Quit()` 메서드를 만들어 Esc와 같은 종료 로직을 쓴다. Editor에서는 플레이를 멈추고, 빌드에서는 `Application.Quit()`을 호출한다.
6. **입력**: 마우스 클릭에 더해 ↑/↓로 포커스를 옮기고 Enter로 선택한다. Esc는 지금처럼 종료로 동작한다.
7. **문구**: 한국어. 출근 / 조작법 / 퇴근 (2026-11-18 사용자 결정: 시작→출근, 종료→퇴근). 아래 규칙의 '시작'·'종료' 버튼은 각각 출근·퇴근 버튼이다.
8. **임시 그래픽**: 아이콘이 필요하면 Bootstrap Icons SVG만 쓴다.
9. **타이틀 로고**(2026-11-18 추가): 메뉴 버튼 위에 `OVER?` / `LOAD!` 두 줄 로고 PNG를 둔다(Bungee 폰트, `tools/title-logo/title-logo.html`로 생성). 부제는 넣지 않는다. 로고 안의 두 줄과 버튼 3개가 하나의 `\` 사선으로 이어지게 왼쪽 끝을 맞춘다.
10. **포커스 강조**: 처음 포커스는 출근에 두지만, 키보드로 포커스를 옮기기 전에는 강조하지 않는다. 마우스는 hover로만 강조한다.
11. **소리**(2026-11-18 추가): 하루 시작 효과음과 BGM은 씬 시작이 아니라 출근을 눌러 하루가 시작될 때 재생한다(`DailyOperationSystem.DayStarted`).

## Tuning Knobs

| Knob | Default | Range | Category | Rationale |
|------|---------|-------|----------|-----------|
| 카메라 블렌드 시간 | 1.5초 | 0.5~3 | feel | 인게임 구도로 돌아가는 속도. 너무 길면 시작이 답답하다. |
| 블렌드 곡선 | EaseInOut | 시네머신 프리셋 | feel | 출발과 도착을 부드럽게 한다. |
| 사선 행 간격(X) | 66px | 0~120 | feel | 0이면 수직 정렬이다. 클수록 `\`가 가파르다. |
| 메뉴 영역 폭 | 화면의 45% | 35~55% | gate | 차량이 왼쪽을 가득 채우는 여백. |
| 시작 후 HUD 표시 시점 | 블렌드 종료 | 블렌드 중 / 종료 후 | feel | 전환 중 화면이 어수선하지 않게 한다. |

값은 `StartScreenConfig`(ScriptableObject, 기존 `DailyOperationConfig`와 같은 방식)에 두고 코드에 하드코딩하지 않는다.

## Acceptance Criteria

- [ ] 플레이 시작 직후 카메라가 `MenuCam` 구도이고, 차량이 화면 왼쪽을 채우며 메뉴 3개가 오른쪽에서 `\` 모양으로 보인다. 기준 사진과 비교한 스크린샷을 `production/qa/evidence/`에 남긴다.
- [ ] 메뉴 동안 하루 시계가 멈춰 있다. 10초 대기 후 시작해도 영업 시각이 시작 시각 그대로다.
- [ ] 메뉴 동안 물류가 생성되지 않고, 차량이 움직이지 않으며, 상호작용도 되지 않는다.
- [ ] 시작을 누르면 카메라가 블렌드 시간 동안 인게임 구도로 이동한다. 이어서 `StartDay()`가 실행되고 조작이 풀린다.
- [ ] 시작 버튼을 연타해도 `StartDay()`는 한 번만 호출된다.
- [ ] 퇴근을 누르면 Editor에서 플레이가 멈춘다. Esc도 같다.
- [ ] 메뉴 동안 BGM이 나오지 않고, 출근 후 BGM이 페이드 인된다.
- [ ] 조작법 버튼은 흐리게 표시되고 눌러도 아무 일도 일어나지 않는다.
- [ ] 키보드 ↑/↓/Enter로도 출근과 퇴근을 선택할 수 있다. 키보드를 쓰기 전에는 출근 버튼이 강조되어 보이지 않는다.
- [ ] 기존 기능 유지: 시작 후의 하루 운영, 정산, HUD 동작은 이전과 같다.

|--------|--------|-----------------|
| DailyOperationSystem | `Start()`의 자동 `StartDay()` 제거 | 코드 수정. 시작 화면이 `StartDay()`를 호출한다. |
| GameManager | `Quit()` 공개 메서드 추가 | 코드 수정. Esc도 `Quit()`을 쓴다. |
| 씬 카메라(Cinemachine) | `MenuCam` 가상 카메라 추가 | 씬 수정(SampleMapDesign). |
| HUD 전체 | 메뉴 동안 숨김, 시작 시 표시 | 시작 화면이 각 HUD 루트를 토글한다. |
| GDD 3.4~3.6(하루 운영) | 하루 시작이 "씬 로드 즉시"에서 "시작 버튼"으로 바뀜 | GDD가 별도로 없으므로 이 스펙이 대체한다. |
