# Quick Design Spec: 주행 방해·내구도 감소 요인 — 구조와 원칙 (초기 기획안)

**Type**: New Small System (프레임워크 한정)
**Scope**: 월드 오브젝트가 주행을 방해하는 방식의 **공통 구조·규칙·경계**만 정한다. 개별 모델의 효과, 수치, 배치는 포함하지 않는다.
**GDD Reference**: `design/game-brief.md`(GDD 없음), `design/gdd/collision-durability-rules.md`
**Date**: 2026-11-16
**Estimated Implementation**: 정적 모듈 골격 약 16h, NPC 기반 골격 약 16~24h. 개별 오브젝트 적용은 후속 작업이다.

## Overview

도로 위 월드 오브젝트를 **정적**과 **동적(NPC)** 두 계열로 나눈다. 정적 오브젝트는 "트리거, 효과, 수명"을 작은 컴포넌트로 조합해 만든다. 모델 리소스가 가진 의미(라바콘은 쓰러지는 물체, 표지판은 지시)를 살려 오브젝트마다 조합을 고른다. 동적 오브젝트는 효과 없이 물리 판정만 받는 능동적 방해물이다. 두 계열 모두 물류 내구도에 관여하지 않는다.

## Core Rules

### R1. 내구도 단일 책임 (확정 원칙)

1. 물류 내구도는 플레이어 차량의 충돌 판정(속도 변화량, `collision-durability-rules.md` 2~3장)에서만 줄어든다.
2. 오브젝트 계열의 컴포넌트는 `Parcel`, `CargoSpec`, 내구도 값과 계산 API를 참조하거나 호출하지 않는다. 피해 배율도 제공하지 않는다. 충돌 문서 5장의 "상대별 피해 배율"은 도입하지 않는다.
3. 오브젝트와 차량이 물리적으로 부딪혀 속도가 변하면, 그 변화량은 플레이어 로직이 기존 규칙으로 판정한다. 오브젝트는 이 판정에 간섭하지 않는다.
4. 효과 모듈이 만든 속도·방향 변경은 충돌이 아니다. 내구도 입력은 물리 충돌 콜백의 접촉에서만 얻는다.

### R2. 계열 구분

| 계열 | 정의 | 효과 컴포넌트 |
|---|---|---|
| 정적 | 스스로 이동하지 않는 3D 모델 리소스(라바콘, 표지판 등). 효과가 있을 수도 없을 수도 있다. | 선택 부착 |
| 동적(NPC) | 스스로 움직이는 능동적 방해물(보행자, 주행 차량) | **부착 금지** |

### R3. 정적 오브젝트의 구성 축 (조합식)

정적 오브젝트 하나는 아래 세 축의 선택으로 정의한다. 축별 선택지는 가칭이며, 개별 기획 단계에서 늘리거나 바꿀 수 있다.

| 축 | 질문 | 선택지(초기) |
|---|---|---|
| 물리 형태 | 월드에 어떻게 존재하나 | 고정 콜라이더 / 비고정 Rigidbody / `isTrigger` |
| 트리거 | 언제 실행되나 | 상호작용(시간 유지) / 충돌 접촉 / 트리거 진입 / 없음 |
| 효과·수명 | 무엇을 하고 어떻게 사라지나 | 효과 0개 이상 + 수명(즉시 제거 / 잔류 후 제거 / 유지) |

- 효과 후보: 최고 속도 영향, 진행 방향 변경, 다른 오브젝트 제거·개방 등. 확정이 아니라 후보 목록이다.
- 효과 컴포넌트는 차량 쪽 인터페이스(가칭 `IVehicleEffectTarget`)로만 영향을 준다. Rigidbody 속도를 직접 쓰지 않는다. 차량 컨트롤러가 요청을 받아 적용한다.
- 효과가 없는 정적 오브젝트(고정 주행 방해)는 컴포넌트 없이 콜라이더만으로 성립한다.
- 오브젝트 하나는 한 번만 실행된다. 같은 효과가 겹치면 가장 강한 것 하나만 적용하고 지속 시간만 갱신한다.

### R4. 패턴 예시 (비규범)

모델별 기획 때 구성 방식을 떠올리기 위한 예시다. 오브젝트 정의가 아니고, 규칙으로 구현하지 않는다.

| 패턴 | 구성 예 |
|---|---|
| 상호작용 | 상호작용 시간을 들여 효과를 일으킨다(막힌 길 개방 등). |
| 비고정-효과 실행 | 부딪히면 밀려나고, 효과를 실행한 뒤 일정 시간 잔류하다 제거된다. |
| 효과 재생 | 트리거 접촉 시 즉시 효과를 내고 잔류 없이 제거된다. |
| 고정-주행방해 | 효과 없이 월드에 박혀 길을 막는다. |

### R5. 동적 오브젝트(NPC)

1. 효과 컴포넌트를 두지 않는다. 변수가 많아지는 것을 막기 위해서다.
2. 물리 판정을 받는 동적(비 키네마틱) Rigidbody로 둔다. 키네마틱은 무한 질량이라 벽과 같아진다(충돌 문서 4장 2번).
3. 이동 규칙(경로, 속도, 질량, 스폰 수)은 모델과 레벨 기획 단계에서 정한다.
4. NPC와의 충돌은 R1에 따라 플레이어 로직이 Δv로만 판정한다. 직접 페널티는 없다(`game-concept.md` 10.2와 일치).
5. 하루 시작 시 활성화하고, 하루 종료 시 조작 잠금과 함께 정지한다.

### R6. 엣지 케이스 (공통)

| 상황 | 결과 |
|---|---|
| 조작 잠금(하루 종료) 중 트리거 접촉 | 효과를 실행하지 않는다. |
| 같은 오브젝트에 동시에 두 번 접촉 | 첫 접촉만 실행한다. |
| 효과 대상 오브젝트가 이미 제거됨 | 아무 일도 하지 않고 오류 없이 넘어간다. |
| 효과 지속 중 하루 종료 | 효과를 해제한다. |
| 효과 컴포넌트가 NPC에 부착됨 | 에디터 검증에서 경고한다. |

## Tuning Knobs

구체 수치는 개별 오브젝트 기획에서 정한다. 이 스펙은 값이 놓일 자리만 정의한다. 모든 값은 데이터(ScriptableObject)로 두고 `TODO(tuning)`으로 표시한다.

| Knob 범주 | 위치 | 비고 |
|---|---|---|
| 효과 파라미터(배율, 지속 시간, 회전량 등) | 효과 컴포넌트 데이터 | 효과마다 다름 |
| 수명(잔류 시간) | 수명 컴포넌트 데이터 | 즉시/잔류/유지 |
| 상호작용 시간 | 기존 `_interactionDuration` | 오브젝트별 |
| 질량·물리 재질 | 프리팹 | 충돌 Δv에 영향. 반발 계수 기준은 충돌 문서 6장 미결정과 연동 |
| NPC 이동·질량·스폰 수 | NPC 데이터 | 레벨 기획과 함께 결정 |

## Acceptance Criteria

- [ ] 정적 오브젝트를 R3의 세 축 조합만으로 프리팹에서 구성할 수 있다. 새 오브젝트를 만들 때 기존 컴포넌트 코드를 수정하지 않는다.
- [ ] 오브젝트 계열 코드가 `Parcel`, `CargoSpec`, 내구도 관련 심볼을 참조하지 않는다(코드 검색으로 확인).
- [ ] 효과 실행만으로는 내구도가 변하지 않고, 같은 접촉에서 내구도가 두 번 줄지 않는다.
- [ ] 한 번 실행한 오브젝트는 다시 실행되지 않는다.
- [ ] NPC에 효과 컴포넌트를 부착하면 에디터 검증이 경고한다.
- [ ] NPC가 동적 Rigidbody로 움직이고, 충돌 시 플레이어 차량이 물리적으로 영향을 받는다.
- [ ] 하루 종료 시 NPC가 정지하고 효과가 해제된다.
- [ ] 회귀: 기존 건물·울타리 충돌과 상·하차 상호작용이 이전과 같다.
