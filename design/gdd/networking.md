## Summary

networking은 2~4명이 한 하루를 나눠 배송하는 협동 배달을 위해, 플레이어와 분리된 서버가 하루 시계·물류·차량 물리·정산의 기준이 되어 참가자 전원이 같은 하루를 보게 하는 기반 시스템이다. 플레이어는 세션을 만들거나 참가해 준비한 뒤 하루를 시작하고, 하루 도중 참가하거나 나가도 하루가 이어진다(호스트 플레이어가 나가면 중단). 협동 배달이라는 이 게임의 멀티플레이 방향(2026-11-21)을 가능하게 하는 시스템이다.

## Overview

networking은 2~4명이 한 물류센터에서 한 하루를 나눠 배송하는 **협동 배달**을 가능하게 하는 기반 시스템이다. 호스트 플레이어가 세션을 열고 나머지가 참가하며, 플레이어 클라이언트와 분리된 서버가 하루 시작과 공유 규칙 상태(게임 시계, 물류 생성, 배송지별 할당 한도, 정산)의 기준이 되어 참가자 전원이 같은 하루를 본다. 호스트 플레이어도 다른 참가자처럼 클라이언트로 참여한다. 각 참가자는 자기 차량을 직접 조작하고 플레이어 차량끼리도 충돌하며, 같은 물류는 한 명만 선택할 수 있다. 배송 결과·수익·별점은 팀 단위로 합산한다. 참가자가 1명인 싱글 플레이도 같은 규칙으로 동작하며 멀티 전용 규칙 분기는 두지 않는다. 플레이어는 세션을 만들거나 참가하고 준비할 때만 이 시스템을 직접 다루고, 하루 중에는 자동으로 동작한다. 이 시스템이 없으면 하루를 둘 이상이 나눠 배송하는 협동 경험 자체가 성립하지 않는다.

## Detailed Design

### Core Rules

1. **구성.** 세션은 서버 1개와 참가자 클라이언트 2~4개로 이루어진다. 싱글은 참가자 1명인 같은 세션이다. 서버는 플레이어 클라이언트와 분리된 실행 단위(별도 프로세스 또는 백그라운드)로 구동하고, 호스트 플레이어도 일반 참가자처럼 클라이언트로 참여한다. 분리 방식·전송·패키지는 ADR에서 정한다. *(사용자 결정, 2026-11-21)*
2. **권한.** 서버가 아래 상태의 유일한 기준이다. 게임 시계(3장), 하루 시작·종료(3.4~3.5), 물류 생성·배송지 할당(4~5장), 물류 상태(예약·적재·내구도·폐기·배송 완료), 모든 차량·NPC의 물리, 보상·정산·별점(11~12장). 클라이언트는 입력과 상호작용 요청만 보내고 서버 결과를 받아 표시한다. 클라이언트가 직접 바꾸는 공유 상태는 없다.
3. **규칙 동일성.** 싱글과 멀티는 규칙이 같다. 인원에 따라 달라질 수 있는 것은 설정 값뿐이다(브리프 Build order 5).
4. **참가.** 참가는 하루 시작 전은 물론 하루 도중에도 정원(4명) 안에서 가능하다. 하루 도중 참가하거나 복귀한 참가자는 이전 상태와 무관하게 최초 상태로 시작한다(Edge Cases). 초과 참가는 거부한다. *(사용자 결정, 2026-11-21: 하루 시작 전 확정 → 하루 중 참가 허용으로 변경)*
5. **하루 시작.** 호스트 플레이어가 하루 시작을 요청하려면 그 시점 Lobby에 있는 다른 참가자 전원이 준비(동의) 상태여야 한다. 호스트 플레이어의 시작 요청이 곧 호스트의 준비다. 조건이 맞으면 서버가 3.4 순서로 초기화하고, 정적 물류가 준비되면 모든 참가자의 조작을 활성화한다. 활성화 신호는 전원에게 한 번에 보내고 서버 시계는 그 순간부터 진행한다. 클라이언트는 수신 즉시 조작을 풀며, 수신 시점 차이는 네트워크 지연만큼 허용한다. *(전원 준비는 사용자 결정, 2026-11-21)*
6. **시간.** 서버 시계만 진행하고 클라이언트는 서버 시각을 받아 표시한다. 영업 종료, 동적 생성 마감, Express 제한 시간, Fresh 신선도 판정은 모두 서버가 3.7 순서로 처리한다. UI를 열어도 시간이 멈추지 않는 규칙(3.2)은 그대로다.
7. **차량과 충돌.** 참가자마다 차량 1대다. 서버가 모든 차량 물리를 시뮬레이션하고, 클라이언트는 조작 입력(방향, 주행 모드, 드리프트, 복구)을 보낸다. 플레이어 차량끼리도 물리 충돌하며 벽·NPC와 같은 기준(10.2의 Δv 판정)을 적용한다. 내구도 감소는 서버가 판정하고, 클라이언트의 충돌 연출(흔들림·소리)은 서버 결과를 받은 뒤 재생한다. 판정 로직은 물리 콜백과 분리한다(`collision-durability-rules.md` 4장 3항). 체급 차이를 반영하려면 모든 차량이 동적 바디여야 한다(같은 문서 4장 2항). *(서버 권한, 사용자 결정, 2026-11-21)*
8. **조작 지연.** 클라이언트 조작이 화면에 반영되기까지의 지연 허용치와 보정 방식은 정하지 않았다 → Open Questions.
9. **물류 예약.** 물류센터 목록은 서버 상태를 모든 참가자가 같게 본다. 참가자가 상차를 시작하면 서버가 그 물류를 그 참가자에게 예약하고, 다른 참가자에게는 선택할 수 없는 "상차 중"으로 표시한다. 예약은 상차 중단(8.4, 복구 실행 포함)이나 접속 끊김 때 풀리고, 상차 완료 시 그 참가자 차량의 적재가 된다. 그룹 전체 선택(8.2)은 처리 순서(7.4)대로 하나씩 예약하며, 이미 예약된 물류는 건너뛴다. *(예약은 사용자 결정, 건너뛰기는 제안, 2026-11-21)*
10. **적재.** 적재 한도와 무게 한도(8.5~8.6), 속도 감소는 차량별로 각자 적용한다. 차량 간 물류 이전은 없다. 예외는 참가자가 이탈해 흩어진 물류를 다른 참가자가 다시 상차하는 경우뿐이다(Edge Cases).
11. **하차·처분.** 하차(9장)와 처분(11.6)은 참가자별로 각자 진행하고, 그 차량에 적재된 물류만 대상이다. 하차 완료와 폐기 전환은 서버가 판정한다. 같은 배송지·처분 장소를 여러 차량이 쓸 수 있는지는 9장·11.6 규칙대로 하며, 이 문서는 제한을 추가하지 않는다.
12. **복구.** 복구(10.6)는 서버가 실행한다. 안전 지점 기록과 복구 위치 결정은 서버의 차량 위치를 기준으로 하고, 복구 후 조작 잠금은 서버가 해당 참가자의 입력을 무시하는 것으로 처리한다. 수치는 10.6을 따른다.
13. **정산·별점.** 서버가 팀 전체를 집계한다. `FinalSettlement`(12.3)는 모든 참가자의 수익·손실 합계이고, `N`·`S`(12.4)는 팀 전체 물류 기준이다. 판정 순서(정산 음수면 별 0개, `N = 0`이면 미표시, `R` 구간)는 12.4 그대로다. 모든 참가자가 같은 정산 화면을 본다. 참가자별 기여 표시는 정하지 않았다 → Open Questions.
14. **하루 종료.** 3.5의 두 조건을 서버가 판정하며, "모든 배송 완료"는 팀 전체 물류 기준이다. 종료되면 서버가 전원의 조작을 동시에 잠그고 정산 화면으로 전환시킨다. 영업 종료 시 진행 중인 상·하차는 미배송 처리한다(3.5).
15. **세션 종료.** 정산을 확인하면 참가자는 메인 화면으로 이동하고 세션은 닫힌다(3.6: 다음 날 운영 없음).
16. **참가 방식.** 호스트 플레이어가 세션을 만들고 다른 참가자가 참가한다. 참가 수단(코드·IP 등)은 정하지 않았다 → Open Questions. 참가는 Lobby·DayStarting·DayRunning에서 가능하고 Settlement에서는 불가능하다(제안).

### States and Transitions

| 상태 | 의미 |
|---|---|
| Closed | 세션 없음 |
| Lobby | 서버 기동, 참가 가능, 하루 시작 전 |
| DayStarting | 3.4 초기화 중, 조작 잠금 |
| DayRunning | 조작 가능, 하루 진행 |
| Settlement | 정산 화면 |

| 전이 | 조건 |
|---|---|
| Closed → Lobby | 호스트 플레이어가 세션 생성(서버 기동) |
| Lobby → DayStarting | 호스트 플레이어가 하루 시작 요청(다른 참가자 전원이 준비 상태여야 함, 그 시점의 참가자 1~4명으로 시작, 이후에도 정원 안에서 참가 가능) |
| Lobby → Closed | 호스트 플레이어가 세션을 닫거나 나감(접속 끊김 포함), 또는 서버 비정상 종료 |
| DayStarting → DayRunning | 정적 물류 준비 완료, 조작 활성화 신호 |
| DayStarting → Closed | 서버 중단(호스트 이탈·비정상 종료). 하루 결과 없음 |
| DayRunning → Settlement | 하루 종료 조건(3.5) |
| DayRunning → Closed | 서버 중단. 하루 결과 없음(호스트 이탈·비정상 종료 처리는 Edge Cases에서 정함) |
| Settlement → Closed | 정산 확인 후 메인 화면 |

참가자가 들어오고 나가는 것(Lobby, DayStarting, DayRunning)은 상태 전이가 아니다.

## Edge Cases

**접속·참가**

- **If 하루 시작 요청 시 참가자가 호스트 플레이어뿐이면**: 준비 조건 없이 호스트 혼자(싱글)로 시작한다. 다른 참가자는 이후에도 참가할 수 있다.
- **If 호스트 플레이어가 하루 시작을 요청했는데 준비하지 않은 참가자가 있으면**: 요청을 거부하고 미준비 참가자를 호스트 플레이어에게 표시한다. *(사용자 결정, 2026-11-21: 하루 시작에 전원 준비(동의) 필요)*
- **If 준비한 참가자가 시작 요청 전에 준비를 취소하면**: 취소를 반영하고 시작 요청은 다시 전원 준비를 요구한다. 시작 요청이 서버에서 수락된 뒤에는 취소할 수 없다.
- **If 준비한 참가자가 Lobby에서 나가면**: 남은 참가자 기준으로 준비 여부를 판정한다.
- **If 새 참가자가 Lobby에 들어오면**: 기존 참가자의 준비는 유지되고, 새 참가자가 준비해야 시작 요청이 가능하다. *(제안)*
- **If 정원(4명)이 찬 세션에 참가를 시도하면**: 거부하고 "정원 초과"를 표시한다.
- **If 정산(Settlement) 중 참가를 시도하면**: 거부하고 "정산 중"을 표시한다. *(제안)*
- **If 참가자가 하루 도중 참가하면(처음 참가든 이탈 후 복귀든 구분 없음)**: 하루 시작 때와 같은 최초 상태(새 차량, 빈 적재, 다른 차량·물체와 겹치지 않는 시작 위치)로 시작한다. 하루 상태(시각, 물류, 흩어진 물류)는 그대로 보여 준다. 하루 도중 참가에는 준비 절차가 없다. *(참가·최초 상태는 사용자 결정, 2026-11-21)*
  - 조작은 참가 직후 활성화한다. DayStarting 중 참가하면 초기화가 끝나 DayRunning이 될 때 다른 참가자와 같은 신호로 활성화한다. *(제안)*
  - 참가·복귀 횟수 제한은 없다. 이탈과 참가를 반복해 차량을 시작 위치로 되돌리는 행동은 막지 않는다(친구 간 협동 전제). *(제안)*
- **If 호스트 플레이어가 하루 도중 나가거나(접속 끊김 포함) 서버가 비정상 종료되면**: 서버도 종료하고 하루를 중단한다. 결과와 정산은 없고, 남은 참가자는 연결 끊김 안내 후 메인 화면으로 이동한다. *(사용자 결정, 2026-11-21)*
- **If Lobby 또는 DayStarting 중 호스트 플레이어가 나가거나(세션 닫기·접속 끊김 포함) 서버가 비정상 종료되면**: 하루 도중과 같게 서버를 종료한다. DayStarting이면 초기화를 중단하고 하루 결과는 없다. 남은 참가자는 연결 끊김 안내 후 메인 화면으로 이동한다. *(제안, 하루 도중 호스트 이탈 결정을 앞 단계로 확장)*
- **If 일반 참가자가 하루 도중 나가면(접속 끊김 포함)**: 그 차량을 제거하고 진행 중인 상·하차·복구를 취소하며 예약을 푼다. 적재한 물류는 차량 위치 주변에 흩어져 물류 오브젝트로 남고(아래), 이미 폐기된 물류는 폐기·페널티 상태를 유지한다(11.6). *(사용자 결정, 2026-11-21)*
- **If 서버가 한 참가자의 입력을 설정 시간 이상 받지 못하면**: 접속 끊김으로 처리해 위 규칙을 적용한다. 그 전까지 입력이 없는 구간은 입력을 0으로 둔다(마지막 입력을 유지하지 않는다). 설정 시간은 `TODO(tuning)`이며 초기값은 정하지 않았다. *(제안)*

**흩어진 물류 오브젝트** *(사용자 결정, 2026-11-21, 아래 제안 표시 항목 제외)*

- 이탈한 참가자의 적재 물류는 하나씩 물류 오브젝트가 되어 차량이 있던 위치 주변 지면에 놓인다. 물류의 데이터(배송지, 배송 유형, 현재 내구도, 남은 제한 시간·신선도, 폐기 여부와 처분 장소 목적지)는 그대로 유지하고, 시간 규칙(7장)도 계속 적용한다.
- 참가한 누구든(이탈했던 본인 포함) 가까이 가서 상호작용 키를 누르고 있으면 그 물류를 상차한다. 소요시간, 적재 한도·무게 한도(8.3, 8.5~8.6), 예약 규칙(Core Rules 9)을 그대로 적용한다. 상차한 뒤의 배송은 일반 물류와 같다.
- 하루 종료까지 배송되지 않으면 일반 미배송과 같이 처리한다(11.4). 이미 폐기된 물류는 페널티를 다시 매기지 않고 정리한다(11.6-6).
- 배치 위치가 접근할 수 없는 곳(맵 밖, 장애물 안, 지면이 아닌 곳)이면 서버가 그 참가자의 마지막 안전 지점(10.6) 주변에 놓는다. 안전 지점이 없으면 10.6 규칙 3의 물류센터 앞 지정 위치를 쓴다. *(제안)*
- 오브젝트끼리 겹치지 않게 서버가 간격을 두고 배치한다. *(제안)*
- 오브젝트는 충돌체가 아닌 상호작용 대상이라 차량 충돌과 내구도에 영향을 주지 않는다. *(제안)*
- 월드 아이콘·나침반 표시와 UI는 UX 단계에서 정한다 → Open Questions.

**물류 예약**

- **If 두 참가자가 같은 물류의 상차를 같은 순간 요청하면**: 서버가 받은 순서대로 처리해 먼저 처리된 참가자가 예약한다. 다른 참가자는 거부 응답을 받고 "상차 중"으로 표시되며 목록이 갱신된다.
- **If 이미 예약된 물류를 오래된 목록 기준으로 요청하면**: 서버가 거부하고 목록을 갱신한다.
- **If 예약한 참가자가 상차를 끝내지 않고 방치하면**: 예약은 물류 한 개의 상차가 진행되는 동안만 유지된다. 입력을 놓거나 UI를 닫으면(8.4) 즉시 풀린다.
- **If 상차 완료와 참가자 이탈이 같은 서버 프레임이면**: 이탈을 먼저 처리한다. 그 참가자의 상차는 완료되지 않고 물류는 있던 자리(물류센터 또는 흩어진 위치)에 남는다. *(제안)*

**충돌·배치**

- **If 한 프레임에 둘 이상의 차량이 충돌하면**: 차량마다 자기 Δv로 판정하고 충돌 쿨다운(0.5초)도 차량별로 적용한다. 두 차량이 서로 부딪히면 양쪽 적재 물류가 각자 감소한다.
- **If 두 차량이 서로를 밀어붙이면**: 충돌 시작 직후 판정 창(0.06초) 밖의 접촉은 감소시키지 않는다(10.2 그대로).
- **If 팀원 차량에 일부러 부딪혀 내구도를 줄이면**: 막지 않는다(친구 간 협동 전제). *(제안)*
- **If 하루 시작 위치나 복구 위치가 다른 차량·물체와 겹치면**: 서버가 지정 위치에서 겹치지 않는 가장 가까운 자리에 배치한다(10.6 복구 위치 규칙 2의 "다른 물체"에 다른 차량을 포함). 겹치지 않는 자리에 놓으므로 배치로 인한 충돌은 없고 내구도는 변하지 않는다. 시작 위치 수(최대 4)와 탐색 범위는 레벨 디자인에서 정한다. *(제안)*

**하루 종료·정산**

- **If 하루 종료(영업 종료)와 하차 완료가 같은 프레임이면**: 3.5·3.7 그대로 미배송으로 처리한다. 판정은 서버 시계로만 한다.
- **If 한 참가자가 마지막 물류를 하차할 때 다른 참가자가 다른 물류를 상차 중이면**: "모든 배송 완료"(3.5 조건 2)는 16.1-1의 기준을 팀 전체 물류에 그대로 적용해 판정한다.
- **If 정산 화면에서 참가자가 이탈하면**: 다른 참가자에게 영향이 없다. 정산 결과는 클라이언트에 전달된 뒤에는 서버가 종료돼도 화면이 유지되며, 서버는 호스트 플레이어가 정산을 확인하면 종료한다. *(제안)*

**서버 규칙과 어긋나는 요청**

- **If 클라이언트 요청이 서버 규칙에 어긋나면**(적재 한도 초과, 이미 처분된 물류 등): 서버가 거부하고 클라이언트 표시를 서버 상태에 맞춘다. 서버 상태가 항상 우선한다.
- **If 클라이언트 표시 시각이 서버와 어긋나면**: 서버 시각으로 맞춘다. 판정은 서버 값만 쓰므로 표시 오차는 결과에 영향이 없다.

## Game Feel

- 가장 중요한 목표는 **자기 차량 입력의 반영 지연**이다. 허용치는 정하지 않았고, AC-NET-13이 측정만 한다.
- 다른 참가자의 차량이 끊겨 보이지 않아야 협동과 충돌 체감이 유지된다. 보간 방식과 허용 오차는 미정이다.
- 충돌 연출은 서버 결과를 받은 뒤 재생되므로 지연만큼 늦다. 받아들일 만한지는 플레이테스트로 확인한다.
- 상차 예약 거부는 요청 직후 응답해야 한다. 허용 지연은 미정이다.

## UI Requirements

- **로비**: 참가자 목록(최대 4명), 참가자별 준비 상태, 준비·준비 취소 버튼, 세션 나가기, 호스트 플레이어의 하루 시작 버튼(전원이 준비되기 전에는 거부 사유 표시).
- **하루 중 HUD**: 다른 참가자 구분 표시, 입·퇴장 토스트, 연결 끊김 안내.
- **물류센터 UI**: 다른 참가자가 상차 중인 물류를 선택할 수 없는 상태로 표시.
- **정산 화면**: 팀 합산 정산과 별점. 참가자별 기여 표시는 미정.
- **흩어진 물류**: 월드 표시와 상호작용 프롬프트(나침반 표시 여부는 미정).
- 참가 수단 UI는 참가 수단이 정해진 뒤 정한다. 새 UI의 구현 방식(Canvas 또는 UI Toolkit)은 UX 단계에서 정한다.

## Acceptance Criteria

> Formulas는 `minimal`이라 쓰지 않았고, 이 시스템의 수치(정원 4명, 판정 창 0.06초 등)는 Core Rules에 인라인이다. 기준은 Core Rules와 Edge Cases에서 가져왔다. 시험 유형: **[자동]** 로직 단위 테스트, **[통합]** 클라이언트 2개 이상을 띄워 확인. 싱글 회귀 확인에는 `production/qa/test-cases/`를 쓴다.

**서버 구성·권한**

- **AC-NET-01 [통합] (규칙 1)** GIVEN 호스트 플레이어가 세션을 만들어 서버가 기동했다, WHEN 호스트 클라이언트와 참가자 클라이언트 1개가 접속한다, THEN 두 클라이언트의 로비 참가자 목록이 같은 2명을 표시한다.
- **AC-NET-02 [통합] (규칙 2)** GIVEN 참가자 2명의 DayRunning, WHEN 한 클라이언트에서 디버그로 로컬 물류 내구도 값을 바꾼다, THEN 서버의 내구도 값은 변하지 않고 그 클라이언트 표시가 서버 값으로 돌아온다.
- **AC-NET-03 [통합] (규칙 3)** GIVEN 참가자 1명(호스트 플레이어만)의 세션, WHEN `production/qa/test-cases/`의 기존 싱글 테스트 케이스를 수행한다, THEN 기존 결과와 같게 모두 통과한다.

**참가·시작**

- **AC-NET-04 [통합] (규칙 4)** GIVEN 참가자 4명이 들어찬 세션, WHEN 5번째 클라이언트가 참가를 시도한다, THEN 참가가 거부되고 "정원 초과"가 표시되며 기존 4명의 상태는 변하지 않는다.
- **AC-NET-05 [통합] (규칙 4)** GIVEN DayRunning 중 참가자 2명, WHEN 새 클라이언트가 참가한다, THEN 새 차량이 겹치지 않는 시작 위치에 빈 적재로 생성되고, 새 클라이언트의 시각·물류 목록이 서버 값과 같으며 참가 직후 조작이 가능하다.
- **AC-NET-06 [통합] (규칙 5)** GIVEN Lobby에 호스트 플레이어와 준비하지 않은 참가자 1명, WHEN 호스트 플레이어가 하루 시작을 요청한다, THEN 요청이 거부되고 미준비 참가자가 호스트 클라이언트에 표시되며 상태는 Lobby로 유지된다.
- **AC-NET-07 [통합] (규칙 5)** GIVEN 참가자가 준비한 상태, WHEN 호스트 플레이어가 하루 시작을 요청한다, THEN 서버가 3.4 순서로 초기화하고 정적 물류가 준비된 뒤 두 클라이언트의 조작이 활성화되며, 두 클라이언트의 시계 표시가 서버 시각과 1게임 분(현실 1초) 이내로 같다. *(합격선은 제안)*
- **AC-NET-08 [통합] (규칙 5)** GIVEN 참가자가 준비했다가 취소했다, WHEN 호스트 플레이어가 하루 시작을 요청한다, THEN 요청이 거부된다.

**시간·충돌**

- **AC-NET-09 [통합] (규칙 6)** GIVEN 참가자 2명의 DayRunning, WHEN 한 클라이언트의 시계 표시를 디버그로 앞당긴다, THEN 영업 종료와 Express 초과 판정 시각은 변하지 않고 서버 시각 기준으로 일어난다.
- **AC-NET-10 [통합] (규칙 7)** GIVEN 두 참가자가 각자 일반 물류를 싣고 차량끼리 정면충돌한다, WHEN 충돌이 판정된다, THEN 각 차량의 감소량이 10.2 산식에 서버가 계산한 자기 Δv를 넣은 값과 같고, 양쪽 클라이언트에 표시된 값이 서버 값과 같다.
- **AC-NET-11 [자동] (규칙 7)** GIVEN 판정 함수에 Δv와 물류 특징을 넣는다, WHEN 계산한다, THEN Δv=5는 일반 −42·Fragile −63, Δv=1.5와 1.49는 0, Δv=6.5와 10은 상한 60(Fragile은 90)이 나온다(10.2 산식과 검산표).
- **AC-NET-12 [통합] (규칙 7)** GIVEN 두 차량이 접촉을 유지한 채 밀어붙인다, WHEN 판정 창(0.06초)이 지난 뒤에도 접촉이 이어진다, THEN 추가 내구도 감소가 없다.
- **AC-NET-13 [통합, 합격선 미정] (규칙 8)** GIVEN 호스트 플레이어가 아닌 클라이언트, WHEN 가속 입력을 보낸다, THEN 입력부터 화면 반영까지의 지연을 측정해 `production/qa/evidence/`에 기록한다. 합격선이 정해지지 않아(Open Questions) 이 항목은 PASS/FAIL을 판정하지 않는다.

**물류 예약·적재·하차**

- **AC-NET-14 [통합] (규칙 9)** GIVEN 두 참가자가 센터에서 같은 물류를 선택했다, WHEN 둘이 같은 순간 상차를 시작한다, THEN 한 명만 예약에 성공하고 다른 한 명은 거부 응답과 "상차 중" 표시를 받으며, 상차 완료 후 그 물류는 성공한 참가자 차량에만 적재된다.
- **AC-NET-15 [통합] (규칙 9)** GIVEN A가 물류 하나를 상차 중이다, WHEN A가 입력을 놓는다, THEN 예약이 풀리고 B가 그 물류를 상차할 수 있다.
- **AC-NET-16 [통합] (규칙 9)** GIVEN B가 그룹의 한 물류를 상차 중이다, WHEN A가 같은 그룹을 그룹 선택으로 상차한다, THEN A는 그 물류를 건너뛰고 다음 물류를 처리 순서대로 상차한다.
- **AC-NET-17 [통합] (규칙 10)** GIVEN A 차량이 적재 한도에 도달했다, WHEN B가 같은 센터에서 상차한다, THEN B의 적재 판정은 B 차량 기준으로만 이루어진다.
- **AC-NET-18 [통합] (규칙 11)** GIVEN A와 B가 각자 폐기 물류를 싣고 처분 장소에 있다, WHEN 둘이 동시에 처분을 진행한다, THEN 각자 자기 차량의 폐기 물류만 처분되고 서버가 각각 완료를 판정한다.
- **AC-NET-19 [통합] (규칙 12)** GIVEN A 차량이 끼어 있고 B가 주행 중이다, WHEN A가 R을 복구 홀드 시간(1초) 동안 누른다, THEN 서버가 10.6 규칙대로 A를 복구하고, B의 차량·적재에는 변화가 없으며, A는 복구 후 2초 동안 입력이 무시된다.

**정산·종료**

- **AC-NET-20 [자동] (규칙 13)** GIVEN 팀 전체 N=10, S=8이고 정산 금액이 0 이상이다, WHEN 하루가 종료된다, THEN 별 2개와 `S/N = 8/10`이 모든 클라이언트에 표시되고 최종 정산은 참가자별 합계와 같다. 경계: 정산 금액이 −1이면 별 0개, N=0이면 별점 미표시.
- **AC-NET-21 [통합] (규칙 14)** GIVEN A의 물류는 모두 하차했지만 B의 적재 물류가 남아 있다, WHEN A가 마지막 하차를 완료한다, THEN 하루는 종료되지 않는다. 팀 전체 물류가 모두 처리된 뒤 마지막 하차가 완료되면, 영업 종료 전이라도 서버가 하루를 종료하고 전원을 정산 화면으로 전환한다.
- **AC-NET-22 [통합] (규칙 15)** GIVEN 정산 화면이다, WHEN 호스트 플레이어가 정산을 확인한다, THEN 서버가 종료되고 호스트는 메인 화면으로 이동하며, 다른 참가자의 정산 화면은 유지되고 그들이 확인하면 메인 화면으로 이동한다.

**이탈·복귀·검증**

- **AC-NET-23 [통합] (Edge)** GIVEN DayRunning 중 참가자 2명, WHEN 호스트 플레이어의 클라이언트가 종료된다, THEN 서버가 종료되고 남은 참가자는 연결 끊김 안내 후 메인 화면으로 이동하며 정산은 생성되지 않는다.
- **AC-NET-24 [통합] (Edge)** GIVEN B 차량에 내구도·남은 제한 시간이 서로 다른 물류 3개가 있다, WHEN B의 접속이 끊긴다, THEN B 차량이 제거되고 물류 3개가 차량 위치 주변에 겹치지 않는 물류 오브젝트 3개로 나타나며, 각 물류의 내구도와 남은 제한 시간은 이탈 직전 값과 같다.
- **AC-NET-25 [통합] (Edge)** GIVEN 흩어진 물류 오브젝트가 있다, WHEN A가 가까이 가서 상호작용 키를 8.3의 상차 소요시간 동안 누른다, THEN 그 물류가 A 차량에 적재되고(한도 이내) 이후 하차까지 일반 물류와 같게 처리된다.
- **AC-NET-26 [통합] (Edge)** GIVEN 하루 종료 시점에 흩어진 물류가 남아 있다, WHEN 정산한다, THEN 그 물류는 미배송으로 집계된다(`N`에 포함, `S`에서 제외).
- **AC-NET-27 [통합] (Edge)** GIVEN 이탈했던 B, WHEN B가 같은 세션에 다시 참가한다, THEN 새 차량이 빈 적재로 시작 위치에 생성되고 이탈 전 상태는 복원되지 않는다.
- **AC-NET-28 [통합] (Edge)** GIVEN 클라이언트가 적재 한도를 초과하는 상차 요청을 강제로 보낸다, WHEN 서버가 받는다, THEN 거부되고 그 클라이언트 표시가 서버 상태로 돌아온다.
- **AC-NET-29 [통합] (Edge)** GIVEN Lobby 또는 DayStarting 상태에 참가자 2명, WHEN 호스트 플레이어의 클라이언트가 종료된다, THEN 서버가 종료되고 남은 참가자는 연결 끊김 안내 후 메인 화면으로 이동하며 하루는 시작되지 않는다.

**기준이 없는 규칙과 구멍**

- 규칙 8(조작 지연 합격선)과 규칙 16(참가 수단)은 정해지지 않아 판정 기준이 없다. AC-NET-13은 측정만 하고, 참가 수단이 정해지면 기준을 추가한다.
- 기준을 아직 못 쓴 Edge Cases: 입력 끊김 판정 시간(값 미정), 상차 완료와 이탈이 같은 프레임인 경우, 시작·복구 위치 겹침 배치(시작 위치 수가 레벨 디자인에서 정해진 뒤), DayStarting 중 참가, 정산 중 참가 거부.
- 네트워크 대역폭·갱신 주기·프레임 예산은 이 문서에서 정하지 않았다. 해당 엔진 참조도 없어서(NOT SOURCEABLE) 성능 기준은 ADR 단계로 넘긴다.

> `qa-lead` 검토 없음 — solo 모드. 제작 전 직접 검토 필요.
