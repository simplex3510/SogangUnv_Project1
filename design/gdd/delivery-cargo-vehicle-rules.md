# 배송·물류·차량 적재 규칙 개정안

> **문서 목적:** 기존 게임 기획서의 배송 및 물류 개념을 분리하고, 배송 유형·물류 생성 방식·물류 특징·차량 적재 규칙을 명확히 정의한다.  
> **기준 문서:** *Over?Load! — 물류 운송 시뮬레이터 Game Design Document v1.1*  
> **개정 기준일:** 2026-11-13  
> **문서 상태:** 신규 규칙 정리안

## 1. 핵심 개념 분리

기존 기획서에서는 '배송'과 '물류'가 일부 문맥에서 혼용될 수 있으므로, 두 개념의 책임과 분류 기준을 분리한다.

### 1.1. 배송 (Delivery)

배송은 물류를 지정된 배송지까지 운송하고 인도하는 **업무 및 서비스의 유형**이다.

배송 유형은 배송의 긴급도와 시간 조건을 정의한다. 물류 객체 자체의 물리적·취급 특성과는 별개로 관리한다.

### 1.2. 물류 (Cargo / Parcel)

물류는 플레이어가 차량에 상차하고 배송지까지 운송하는 **개별 운송 대상 객체**이다.

물류는 생성 방식과 취급 특징을 각각 가진다.  
배송 유형은 해당 물류가 수행해야 하는 배송 조건을 나타내며, 물류의 취급 특징과 독립적으로 조합될 수 있다.

### 1.3. 개념별 분류 체계

| 구분 | 분류 기준 | 종류 |
|---|---|---|
| 배송 | 배송 서비스의 시간 조건 | 일반 배송(Normal), 신속 배송(Express) |
| 물류 생성 방식 | 물류가 생성되는 시점 | 정적 생성(Static), 동적 생성(Dynamic) |
| 물류 특징 | 물류의 취급 및 적재 특성 | 취급주의(Fragile), 고중량(Heavy), 대형(Large) |
| 물류 객체 프로퍼티 | 개별 물류가 보유하는 값 | 내구도(Durability) |
| 차량 프로퍼티 | 차량이 수용할 수 있는 적재량 | 적재 한도(Cargo Capacity), 무게 한도(Weight Capacity) |

> **구분 원칙**
>
> - 배송: 어떤 조건으로 배송하는가
> - 물류 생성 방식: 언제 어떻게 물류가 만들어지는가
> - 물류 특징: 해당 물류를 어떻게 취급하고 적재해야 하는가

## 2. 배송 유형 (Delivery Type)

배송 유형은 물류에 부여되는 배송 서비스의 종류다. 현재 두 가지 유형을 사용한다.

| 항목 | 일반 배송 (Normal) | 신속 배송 (Express) |
| --- | --- | --- |
| 배송 긴급도 | 일반 | 상대적으로 높음 |
| 제한 시간 | 없음 | 있음 |
| 제한 시간 관리 | 해당 없음 | 물류별 배송 제한 시간 적용 |
| 제한 시간 초과 패널티 | 해당 없음 | 시간 추가 보상 미지급 +  시간 초과 손실 적용 |
| 제한 시간 추가 보너스 | 해당 없음 | 시간 제한 추가 보상 지급 |
| 거리 기반 추가 보너스 | 배송 거리 비례 보상 적용 | 배송 거리 비례 보상 적용 |
| 기본 리워드 | 지급 | 지급 |

### 2.1. 일반 배송 (Normal)

- 배송 제한 시간이 없는 일반적인 배송이다.
- 배송 완료 시 기본 보상과 거리 기반 추가 보상을 지급한다.
- 배송 제한 시간이 없으므로 시간 초과 및 시간 내 배송 보상 판정을 적용하지 않는다.

### 2.2. 신속 배송 (Express)

- 배송 제한 시간이 부여되는 긴급 배송이다.
- 배송 제한 시간은 거리 기반으로 물류가 생성될 때 결정한다.
- 제한 시간 내 배송을 완료하면 기본 보상, 거리 기반 추가 보상, 시간 추가 보상을 지급한다.
- 제한 시간을 초과한 뒤 배송을 완료하면 기본 보상과 거리 기반 추가 보상은 지급하되, 시간 추가 보상은 지급하지 않는다.
  - 시간 초과 손실 적용 여부와 산식은 기존 시간 초과 규칙을 기준으로 관리한다.
- 배송 제한 시간 초과는 배송 실패를 의미하지 않는다. 배송 자체의 성공 여부와 시간 조건 충족 여부는 별도로 판정한다.

### 2.3. 배송 성공 및 실패 (Delivery Success & Failure)

배송의 성공과 실패는 배송 제한 시간의 초과 여부가 아닌, 영업 종료 시점까지 배송을 완료했는지를 기준으로 판정한다.

| 배송 상황 | 판정 | 보상 | 손실 |
| --- | --- | --- | --- |
| Normal 배송 완료 | 성공 | 기본 배송료 + 거리 추가 배송료 | - |
| Express 제한 시간 내 배송 완료 | 성공 | 기본 배송료 + 거리 추가 배송료 + 시간 추가 보상 | - |
| Express 제한 시간 초과 후 배송 완료 | 성공 | 기본 배송료 + 거리 추가 배송료 | 시간 초과 손실 |
| 영업 종료 시 미배송 | 실패 | (배송 보상 미지급) | 배송 실패 손실 |

> **주의:**
> 배송 제한 시간 초과는 배송 실패를 의미하지 않는다.  
> 시간 초과 손실은 배송을 완료한 물류에 적용하며, 배송 실패 페널티는 영업 종료까지 배송하지 못한 물류에 적용한다.

## 3. 물류 생성 방식 (Cargo Generation Type)

물류 생성 방식은 물류가 생성되는 시점을 기준으로 구분한다.  
생성 방식은 배송 유형 및 물류 특징과 독립적으로 관리한다.

| 항목 | 정적 생성 (Static) | 동적 생성 (Dynamic) |
| --- | --- | --- |
| 생성 시점 | 플레이 시작 전, 하루 운영 준비 단계 | 플레이 도중 |
| 생성 목적 | 하루 운영 시작 시점의 기본 배송 물량 구성 | 운영 중 추가 배송 물량 공급 |
| 배송지 할당 | 생성 시 배송지에 할당 | 생성 시 배송지에 할당 |
| 생성량 및 간격 | 기존 정적 생성 설정 적용 | 기존 동적 생성량·생성 간격 설정 적용 |

## 4. 물류 특징 (Cargo Traits)

물류 특징은 개별 물류의 취급 난이도와 차량 적재량에 영향을 주는 속성이다.  
하나의 물류에 여러 특징이 함께 부여될 수 있다.

| 특징 | 식별자 | 주요 효과 | 설명 |
| --- | --- | --- | --- |
| 취급주의 | `Fragile` | 내구도 감소 | 일반 물류보다 내구도가 낮은 물류 |
| 고중량 | `Heavy` | 무게 한도 사용량 증가 | 차량에 적재할 때 일반 물류보다 더 많은 무게 적재량을 차지하는 물류 |
| 대형 | `Large` | 적재 한도 사용량 증가 | 차량에 적재할 때 일반 물류보다 더 많은 적재 용량을 차지하는 물류 |

### 4.1. 취급주의 (Fragile)

- 일반 물류보다 내구도가 낮다.
- 물류 객체의 내구도(Durability) 프로퍼티를 통해 내구도를 관리한다.
- 취급주의 특징은 내구도 값에 반영한다.

### 4.2. 고중량 (Heavy)

- 차량에 상차할 때 일반 물류보다 더 많은 무게 적재량을 차지한다.
- 차량의 무게 한도(Weight Capacity)를 더 빠르게 소모한다.
- 실제 물리 질량이나 차량의 물리 거동을 변경하는 용도로 사용하지 않는다.
- 게임 규칙상 적재 한도 판정에만 사용하는 추상적인 수치로 처리한다.

### 4.3. 대형 (Large)

- 차량에 상차할 때 일반 물류보다 더 많은 적재 용량을 차지한다.
- 차량의 적재 한도(Cargo Capacity)를 더 빠르게 소모한다.
- 실제 물류 부피나 충돌 크기 등 물리적 특성을 구현하는 의미는 아니다.
- 게임 규칙상 적재 한도 판정에만 사용하는 추상적인 수치로 처리한다.

### 4.4. 특징 조합 및 보상

- 하나의 물류에 여러 물류 특징이 함께 부여될 수 있다.
- 물류에 부여된 특징이 많을수록 해당 물류의 보상이 강화된다.
- 특징별 보상 증가량 및 복수 특징의 보상 산식은 밸런싱 단계에서 결정한다.
- 특징의 보상 효과는 배송 유형의 보상 조건과 함께 적용한다. 단, 구체적인 중첩 산식은 별도 확정이 필요하다.

## 5. 물류 객체 프로퍼티

물류 객체는 개별 상태와 적재·보상 계산에 필요한 데이터를 보유한다.

| 프로퍼티 | 식별자 | 설명 |
| --- | --- | --- |
| 내구도 | `Durability` | 물류 객체가 보유하는 내구도 값. 취급주의(`Fragile`)는 일반 물류보다 낮은 값을 가진다. |

### 관련 기획 미결 사항

다음은 현재 기획안에서 확정하지 않으며, 추가 기획이 필요하다.

- 충돌 세기 판정 기준과 내구도 감소량 산식
- 내구도 0 도달 시 처리
- 내구도와 배송 보상의 연계 방식

> 2026-11-14 `game-design.md` 1.3 개정으로 차량 충돌은 적재된 물류의 내구도를 감소시키는 것으로 확정되었다(10.2).  
> 감소량 산식 등 세부 규칙은 `game-design.md` 16.6에서 관리한다.

## 6. 차량 적재 프로퍼티 및 적재 규칙

차량은 서로 독립적인 두 가지 적재 한도를 가진다.

| 프로퍼티 | 식별자 | 판정 대상 | 초과 가능 여부 |
| --- | --- | --- | --- |
| 적재 한도 | `Cargo Capacity` | 물류의 적재 용량 사용량 | 불가 |
| 무게 한도 | `Weight Capacity` | 물류의 무게 적재량 사용량 | 불가 (미정: 6.4절 참고) |

### 6.1. 적재 한도 (Cargo Capacity)

- 차량이 수용할 수 있는 적재 용량의 총량이다.
- 일반 물류는 기본 적재 용량을 사용한다.
- 대형(Large) 물류는 일반 물류보다 더 많은 적재 용량을 사용한다.
- 적재 한도를 초과하는 물류는 상차할 수 없다.

### 6.2. 무게 한도 (Weight Capacity)

- 차량이 수용할 수 있는 무게 적재량의 총량이다.
- 일반 물류는 기본 무게 적재량을 사용한다.
- 고중량(Heavy) 물류는 일반 물류보다 더 많은 무게 적재량을 사용한다.
- 무게 한도를 초과하는 물류는 상차할 수 없다.
- 무게 적재량은 물리 시뮬레이션에 직접 반영하지 않고, 적재 가능 여부를 판정하기 위한 추상적인 게임 규칙으로 사용한다.

### 6.3. 상차 가능 조건

물류를 상차하려면 다음 두 조건을 모두 만족해야 한다.

1. 상차 후 총 적재 용량 사용량이 차량의 적재 한도 이하여야 한다.
2. 상차 후 총 무게 적재량 사용량이 차량의 무게 한도 이하여야 한다.

두 조건 중 하나라도 만족하지 못하면 해당 물류를 상차할 수 없다.

| 적재 한도 판정 | 무게 한도 판정 | 결과 |
|---|---|---|
| 이내 | 이내 | 상차 가능 |
| 초과 | 이내 | 상차 불가 |
| 이내 | 초과 | 상차 불가 |
| 초과 | 초과 | 상차 불가 |

### 6.4. 한도 초과에 대한 향후 확장

현재 규칙에서는 적재 한도와 무게 한도 모두 초과 적재를 허용하지 않는다.

향후 무게 한도 초과 적재를 허용하는 방향으로 확장할 경우, 초과 무게에 비례하여 차량의 최대 속도를 감소시키는 별도 규칙과 밸런싱이 필요하다.

이는 현재 확정 규칙이 아니며 후속 기획 범위로 둔다.

## 7. 보상 규칙 요약

물류 보상은 배송 거리, 배송 유형의 시간 조건, 물류 특징을 기준으로 구성한다.

| 보상 요소 | 적용 조건 | 효과 |
|---|---|---|
| 기본 보상 | 배송 완료 | 기본 배송 보상 지급 |
| 거리 기반 추가 보상 | 배송 완료 | 물류센터와 배송지 사이의 거리에 비례하여 보상 증가 |
| 시간 추가 보상 | 신속 배송(Express)을 제한 시간 내 배송 완료 | 추가 보상 지급 |
| 물류 특징 보상 | 물류에 특징이 부여된 경우 | 특징이 많을수록 보상 강화 |

### 7.1. 배송 거리와 보상

- 물류가 배송되는 거리에 비례하여 더 많은 보상을 지급한다.
- 거리 계산 기준과 실제 보상 산식은 기존 거리 기반 보상 규칙 및 밸런싱 설정을 따른다.

### 7.2. 배송 제한 시간과 보상

- 일반 배송(Normal)은 시간 제한이 없으므로 시간 추가 보상 판정을 적용하지 않는다.
- 신속 배송(Express)은 제한 시간 내 배송을 완료하면 시간 추가 보상을 지급한다.
- 신속 배송의 제한 시간을 초과하더라도 배송 자체는 완료할 수 있다. 다만 시간 추가 보상은 지급하지 않는다.

### 7.3. 물류 특징과 보상

- 물류 특징이 추가될수록 보상을 강화한다.
- 특징별 가산 방식, 특징 조합 시 중첩 방식, 보상 상한은 추후 밸런싱에서 확정한다.
- 취급주의·고중량·대형의 적재 및 내구도 효과와 보상 효과는 서로 다른 규칙으로 관리한다.

## 8. 물류 데이터 구성 방향

물류 데이터는 서로 다른 분류 축을 혼합하지 않도록 구성한다.

| 데이터 영역 | 포함 정보 | 목적 |
|---|---|---|
| 식별 및 할당 | 물류 ID, 배송지 ID | 개별 물류 식별 및 배송지 연결 |
| 배송 조건 | 배송 유형(Normal/Express), 제한 시간 관련 데이터 | 배송 서비스 조건 관리 |
| 생성 정보 | 생성 방식(Static/Dynamic), 생성 시각 | 물류 생성 이력 및 생성 규칙 구분 |
| 물류 특징 | `Fragile`, `Heavy`, `Large` 등 부여된 특징 | 취급·적재·보상 효과 판정 |
| 물류 프로퍼티 | 내구도(Durability) | 물류 자체 상태 관리 |
| 적재 사용량 | 적재 용량 사용량, 무게 적재량 | 차량 적재 가능 여부 판정 |
| 보상 정보 | 기본 보상, 거리 보상, 시간 추가 보상, 특징 보상 | 배송 완료 시 보상 계산 |

배송 유형, 생성 방식, 물류 특징은 서로 다른 분류 축이다. 예를 들어 하나의 물류는 다음과 같이 조합될 수 있다.

| 예시 | 배송 유형 | 생성 방식 | 물류 특징 |
|---|---|---|---|
| A | Normal | Static | 없음 |
| B | Express | Static | Fragile |
| C | Normal | Dynamic | Heavy |
| D | Express | Dynamic | Fragile + Large |
| E | Normal | Static | Heavy + Large |

위 조합은 분류 구조를 설명하기 위한 예시이며, 각 조합의 생성 확률이나 허용 여부를 확정하는 것은 아니다.

## 10. 추가 확정이 필요한 사항

이번 개정안에서 개념과 기본 동작은 정의했지만, 아래 세부 규칙은 아직 확정되지 않았다. 구현자가 임의로 수치를 정하거나 기존 규칙을 확대 해석하지 않도록 별도 결정이 필요하다.

| 항목 | 미결정 내용 |
|---|---|
| 일반 물류 기준값 | 일반 물류의 기본 내구도, 적재 용량 사용량, 무게 적재량 |
| Fragile | 취급주의 물류의 내구도 수치 및 내구도 감소 조건 |
| 내구도 결과 | 내구도 0 도달 시 처리, 배송 성공·보상과의 관계 |
| Heavy | 고중량 물류의 무게 적재량 계수 또는 고정 사용량 |
| Large | 대형 물류의 적재 용량 사용량 계수 또는 고정 사용량 |
| 특징 생성 | 특징별 생성 확률, 복수 특징 부여 가능 여부 및 조합 규칙 |
| 특징 보상 | 특징별 보상 증가량, 복수 특징 중첩 산식, 보상 상한 |
| 배송 보상 | 거리 비례 보상 산식 및 특징 보상과의 결합 순서 |
| Express 제한 시간 | 거리 기반 제한 시간 산식 및 시간 편차 |
| 차량 적재 한도 | 차량의 적재 한도 및 무게 한도 기본값 |
| 초과 적재 확장 | 무게 한도 초과 허용 시 최대 속도 감소 산식과 적용 범위 |

### 10.1. 기존 규칙과의 충돌 검토

기존 기획서에는 모든 물류의 배송 제한 시간이 생성 시점부터 감소한다고 서술되어 있다. 이번 개정안에서는 Normal에 시간 제한이 없고 Express에만 시간 제한이 있으므로, 해당 규칙은 **Express 물류에만 적용**하도록 수정해야 한다.

또한 기존 기획서의 '무게 및 부피에 따른 차이는 구현하지 않는다'는 문구는 이번 개정안의 Heavy·Large 적재량 판정과 충돌한다. 실제 물리 시뮬레이션은 도입하지 않되, 적재 가능 여부를 판단하는 추상적인 사용량은 구현 범위에 포함하도록 문구를 교체해야 한다.

## 11. 핵심 규칙 요약

1. 배송과 물류는 서로 다른 개념으로 관리한다.
2. 배송 유형은 일반 배송(Normal)과 신속 배송(Express)으로 구분한다.
3. Normal은 배송 제한 시간이 없으며, Express는 배송 제한 시간이 있다.
4. 물류 생성 방식은 정적 생성(Static)과 동적 생성(Dynamic)으로 구분한다.
5. 물류 특징은 취급주의(Fragile), 고중량(Heavy), 대형(Large)으로 구분한다.
6. Fragile은 일반 물류보다 내구도가 낮다.
7. Heavy는 차량의 무게 한도 사용량을 더 많이 차지한다.
8. Large는 차량의 적재 한도 사용량을 더 많이 차지한다.
9. Heavy와 Large의 효과는 물리 시뮬레이션이 아닌 적재 가능 여부 판정에만 반영한다.
10. 물류 객체는 내구도(Durability) 프로퍼티를 가진다.
11. 물류 특징이 많을수록 보상이 강화된다.
12. 배송 거리가 길수록 거리 기반 보상이 증가한다.
13. Express를 제한 시간 내 배송하면 시간 추가 보상을 지급한다.
14. 차량은 적재 한도(Cargo Capacity)와 무게 한도(Weight Capacity)를 각각 가진다.
15. 두 한도 중 하나라도 초과하면 해당 물류를 상차할 수 없다.
16. 무게 한도 초과 적재와 초과 무게에 따른 최대 속도 감소는 후속 확장 사항이다.
