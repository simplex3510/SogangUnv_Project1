# 1. 게임 개요

## 1.1. 게임 콘셉트

플레이어가 운송 차량을 직접 조작하여 물류센터에서 물류를 상차하고, 각 물류에 지정된 배송지까지 운송한 뒤 하차하는 캐주얼 배달 운송 시뮬레이터이다.

플레이어는 물류센터에서 배송할 물류를 선택하고, 차량의 적재 한도와 각 물류의 배송 제한 시간을 고려하여 배송 계획을 세운다. 이후 차량을 직접 운전하여 여러 배송지를 방문하고 배송을 완료한다.

배송 완료를 통해 수익을 획득하며, 장기적으로는 획득한 수익을 활용하여 차량과 물류센터의 능력을 개선하고 더욱 효율적인 배송을 수행하는 것을 목표로 한다.

현재 마일스톤에서는 기본 배송 루프와 배송 과정에서 발생하는 조작 및 판단의 재미를 검증하는 데 집중한다. 성장 및 업그레이드 시스템은 후속 개발 범위로 둔다.

## 1.2. 게임 핵심 재미

### 핵심 재미

1. **배송 과정 전체의 재미**
   - 물류 선택, 상차, 운송, 배송, 하차로 이어지는 전 과정을 직접 수행한다.
   - 배송지별 물류량과 배송 제한 시간을 고려하여 배송 순서를 결정한다.

2. **차량 조작의 통제감**
   - 플레이어가 직접 차량을 조작하여 원하는 경로로 이동한다.
   - 장애물과 도로 환경에 대응하며 목적지에 도달한다.

3. **배송 계획 및 판단**
   - 차량 적재 한도를 고려하여 물류를 선택한다.
   - 각 물류의 남은 배송 제한 시간을 고려하여 상차 및 하차 우선순위를 결정한다.
   - 배송지 방문 순서를 직접 결정한다.

4. **배송 완료와 성취감**
   - 배송 제한 시간 내 배송을 완료하여 추가 보상을 획득한다.
   - 배송을 반복하여 하루의 운영 목표를 달성한다.

### 보조 재미

- 고정 장애물과 같은 환경적 방해 요소를 극복하는 재미
- 후속 업데이트에서 도입할 수 있는 경찰 추격 시스템의 긴장감

경찰 추격 시스템은 현재 마일스톤의 범위에 포함하지 않는다.

## 1.3. 핵심 게임 루프

```text
물류센터에서 배송 물류 확인
        ↓
배송할 물류 선택
        ↓
차량에 물류 상차
        ↓
배송 경로 및 순서 판단
        ↓
차량 운전 및 배송지 이동
        ↓
배송지에서 물류 하차
        ↓
배송 보상 획득
        ↓
남은 물류 배송 또는 물류센터 재방문
        ↓
하루 운영 종료 또는 모든 배송 완료
        ↓
일일 정산
```

플레이어는 정해진 배송 경로를 따라가는 것이 아니라, 현재 적재된 물류와 배송 제한 시간을 고려하여 배송 순서를 자유롭게 결정한다.

# 2. 플레이어 조작 및 상호작용

## 2.1. 기본 조작

| 입력 | 기능 |
|---|---|
| ↑ | 전진 입력 |
| ← | 좌회전 입력 |
| ↓ | 후진 입력 |
| → | 우회전 입력 |
| ctrl | 주행 모드 전환 |
| shift | 드리프트 (회전 입력 필요) |
| Spacebar | 상호작용 |

차량 이동과 관련된 세부 조작 감도 및 물리 수치는 밸런싱 및 구현 단계에서 조정한다.

## 2.2. 상호작용 대상

상호작용 대상 건물은 다음 두 가지로 구성한다.

| 대상 | 기능 |
|---|---|
| 물류센터 | 배송 물류 확인 및 상차 |
| 배송지 | 해당 배송지에 할당된 물류 하차 |

상호작용 키(기본 Spacebar)는 상호작용 대상에 접근하여 UI를 호출하는 기능과 상호작용 작업을 수행하는 기능으로 사용한다.

상호작용 작업은 상호작용 키를 누르고 있는 동안 진행되며, 작업 대상 및 상황에 따라 상차 또는 하차를 수행한다.

# 3. 하루 운영 및 게임 시간 시스템

## 3.1. 기본 운영 시간

하루 운영은 게임 내 시간 기준으로 진행한다.

| 항목 | 기본값 | 설정 정책 |
|---|---:|---|
| 영업 시작 시각 | 09:00 | Unity Editor에서 변경 가능 |
| 영업 종료 시각 | 18:00 | Unity Editor에서 변경 가능 |
| 동적 물류 생성 마감 | 16:00 | 영업 종료 시각 2시간 전 |
| 첫 동적 물류 생성 가능 시각 | 09:00 | Unity Editor에서 변경 가능 |

실제 운영 시간은 Unity Editor에서 조정할 수 있도록 구성한다.

동적 물류 생성 마감은 별도 고정 시각보다는 영업 종료 시각에서 2시간을 차감하여 계산한다.

`DynamicSpawnEndTime = BusinessEndTime - 2 hours`

## 3.2. 게임 시간 진행

- 게임 시간은 현실 시간보다 빠르게 진행한다.
- 시간 배속은 고정값을 사용한다.
- 플레이어는 게임 내 시간 배속을 변경할 수 없다.
- 현재 마일스톤에서는 일시정지 및 시간 배속 변경 기능을 제공하지 않는다.
- 배송 제한 시간, 동적 물류 생성 및 하루 종료는 동일한 게임 시간 기준을 사용한다.
- 상차 및 하차 중에도 게임 시간은 정상적으로 진행된다.
- 상차 및 하차 중에도 물류의 배송 제한 시간은 감소한다.

게임 시간 배속의 구체적인 수치는 밸런싱 단계에서 결정한다.

## 3.3. 게임 시간 UI

게임 플레이 화면에는 현재 게임 내 시각을 표시한다.

- 표시 형식: `HH:mm`
- 예시: `09:30`, `14:45`
- 영업 종료까지 남은 시간은 별도로 표시하지 않는다.
- 정산 화면에서는 게임 내 시계를 표시하지 않는다.

개별 물류의 배송 제한 시간은 물류별 프로그레스 바로 확인할 수 있다.

## 3.4. 하루 시작 처리

하루가 시작되면 다음 순서로 초기화한다.

1. 게임 내 시각을 영업 시작 시각으로 설정한다.
2. 하루 운영 관련 데이터를 초기화한다.
3. 배송지별 일일 누적 할당량을 초기화한다.
4. 하루 동적 물류 생성 가능량을 결정한다.
5. 정적 물류 생성량을 결정한다.
6. 정적 물류를 생성하고 배송지에 할당한다.
7. 정적 물류 생성이 완료되면 플레이어 조작을 활성화한다.

정적 물류가 모두 준비되기 전에는 플레이어가 게임을 시작할 수 없다.

## 3.5. 하루 종료 조건

하루 운영 종료 조건은 다음 두 가지이다.

### 조건 1. 영업 종료 시각 도달

게임 내 시계가 영업 종료 시각에 도달하면 즉시 하루 운영을 종료한다.

- 차량 이동을 중단한다.
- 진행 중인 상차 및 하차 작업을 중단한다.
- 물류센터 및 배송지 상호작용을 종료한다.
- 배송이 완료되지 않은 물류를 미배송 처리한다.
- 일일 정산 화면으로 전환한다.

영업 종료 시점에 하차가 진행 중이더라도 실제 하차 완료 판정이 이루어지지 않았다면 미배송으로 처리한다.

### 조건 2. 모든 배송 완료

하루에 처리해야 할 모든 배송이 완료되면 영업 종료 시각에 도달하지 않았더라도 하루 운영을 조기 종료한다.

**중요:** 배송지별 일일 할당 한도 소진은 하루 조기 종료 조건이 아니다. 할당 한도 소진은 해당 배송지에 신규 물류를 더 이상 할당할 수 없다는 의미이다.

## 3.6. 하루 종료 이후

- 일일 정산 화면으로 전환한다.
- 정산 화면에서는 게임 내 시계를 표시하지 않는다.
- 다음 운영이 시작될 경우 게임 내 시각은 영업 시작 시각으로 초기화한다.
- 현재 마일스톤에서는 다음 날 운영 및 물류 이월 기능을 구현하지 않는다.

# 4. 물류 생성 시스템

물류는 정적 물류와 동적 물류 두 가지 유형으로 구분한다.

## 4.1. 정적 물류 (Initial Deliveries)

정적 물류는 하루 운영 시작 시 사전에 생성되는 기본 물류이다.

### 생성 규칙

- 하루 시작 시 생성한다.
- 생성량은 설정된 최소·최대 범위 내에서 무작위로 결정한다.
- 생성된 물류는 배송지에 무작위로 할당한다.
- 배송지별 일일 누적 할당 한도를 적용한다.
- 정적 물류 생성량이 배송지 전체 잔여 할당량을 초과하면 잔여 할당량까지만 생성한다.
- 동적 물류와 동일한 배송 타입 생성 확률을 적용한다.
- 물류 생성이 완료된 이후 플레이어 조작을 활성화한다.

정적 물류 생성량은 Unity Editor에서 조정할 수 있도록 한다.

## 4.2. 동적 물류 (Dynamic Deliveries)

동적 물류는 하루 운영 중 무작위 시점에 추가로 생성되는 물류이다.

### 생성 규칙

- 하루 시작 시 동적 물류의 하루 생성 가능량을 최소·최대 범위 내에서 무작위 결정한다.
- 첫 생성 가능 시각은 별도 설정값으로 관리한다.
- 첫 생성 가능 시각의 기본값은 영업 시작 시각인 09:00이다.
- 첫 생성 이후의 물류 생성 간격은 설정된 최소·최대 범위 내에서 무작위로 결정한다.
- 다음 생성 시각은 이전 물류의 실제 생성 시점을 기준으로 계산한다.
- 동적 물류는 영업 종료 2시간 전부터 신규 생성을 중단한다.
- 기본 운영 시간 기준 생성 마감은 16:00이다.
- 동적 물류 생성은 배송지별 일일 누적 할당 한도를 공유한다.
- 하루 생성 가능량은 생성에 성공할 때마다 1씩 차감한다.
- 정적 물류와 동일한 배송 타입 생성 확률을 적용한다.

### 동적 물류 생성 실패

동적 물류 생성 시 할당 가능한 배송지가 존재하지 않는다면 해당 생성은 취소한다.

이 경우:

- 다른 배송지를 재검색하거나 대기열에 등록하지 않는다.
- 생성 실패 이후 재시도하지 않는다.
- 동적 물류 생성 시스템 자체를 종료한다.
- 기존에 생성된 물류의 배송 및 상차에는 영향을 주지 않는다.

동적 물류 생성 시스템의 종료는 하루 운영의 종료를 의미하지 않는다. 플레이어는 기존 물류를 계속 배송할 수 있다.

## 4.3. 동적 물류 생성 마감 이후

동적 물류 생성 마감과 물류센터 운영 종료는 별개의 규칙으로 처리한다.

| 기능 | 생성 마감 이후 ~ 영업 종료 이전 |
|---|---|
| 신규 동적 물류 생성 | 중단 |
| 기존 물류 확인 | 가능 |
| 기존 물류 상차 | 가능 |
| 배송지 방문 | 가능 |
| 물류 하차 | 가능 |
| 배송 제한 시간 감소 | 계속 진행 |

동적 물류 생성이 중단되더라도 물류센터의 상차 기능은 영업 종료 전까지 정상적으로 이용할 수 있다.

# 5. 배송지 할당 시스템

## 5.1. 배송지별 일일 할당 한도

각 배송지는 하루 동안 할당받을 수 있는 물류의 최대 개수를 가진다.

배송지별로 다음 데이터를 관리한다.

| 데이터 | 설명 |
|---|---|
| DailyAssignedCount | 당일 누적 할당 물류 개수 |
| MaxDailyAssignmentCount | 하루 최대 할당 가능 개수 |

배송지가 물류를 할당받을 때 `DailyAssignedCount`를 1 증가시킨다.

배송 완료 여부와 관계없이 누적 할당량은 감소하지 않는다.

즉, 물류를 배송 완료해도 배송지의 일일 할당 가능량은 복구되지 않는다.

## 5.2. 배송지 할당 규칙

물류가 생성될 때 할당 가능한 배송지 중 하나를 무작위로 선택한다.

할당 가능한 배송지는 다음 조건을 만족해야 한다.

`DailyAssignedCount < MaxDailyAssignmentCount`

할당 규칙:

- 정적 물류와 동적 물류는 동일한 할당 규칙을 사용한다.
- 현재 할당 가능한 배송지 후보 중 하나를 균등 확률로 선택한다.
- 배송지별 잔여 할당량에 따른 가중치는 적용하지 않는다.
- 일일 할당 한도가 소진된 배송지는 후보에서 제외한다.
- 배송지별 할당 한도를 초과하여 물류를 배정할 수 없다.

## 5.3. 할당 한도 소진 처리

모든 배송지의 일일 할당 한도가 소진되면 신규 물류를 할당할 수 없다.

이 상태는 신규 동적 물류 생성의 실패 조건이 될 수 있으며, 해당 조건으로 동적 물류 생성 시스템이 종료될 수 있다.

그러나 할당 한도 소진 자체는 하루 운영 종료 조건이 아니다.

이미 생성된 물류가 남아 있다면 플레이어는 해당 물류의 배송을 계속 수행해야 한다.

하루 조기 종료는 모든 배송이 완료되었을 때만 발생한다.

# 6. 물류 데이터 및 배송 타입

## 6.1. 물류 데이터

각 물류는 독립적인 데이터로 관리한다.

주요 데이터 항목은 다음과 같다.

- 물류 고유 식별자
- 할당된 배송지
- 배송 타입
- 생성 시각
- 배송 제한 시간
- 남은 배송 제한 시간
- 배송 진행 상태
- 기본 배송료
- 거리 추가 배송료
- 시간 추가 보상
- 시간 초과 여부

배송 제한 시간과 보상 관련 데이터는 물류 생성 시점에 결정하여 해당 물류 데이터에 저장한다.

이를 통해 물류 생성 이후 설정값이 변경되더라도 이미 생성된 물류의 조건이 임의로 변경되지 않도록 한다.

## 6.2. 배송 타입

현재 마일스톤에서는 다음 두 가지 배송 타입을 구현한다.

| 배송 타입 | 식별자 | 특징 |
|---|---|---|
| 일반 배송 | Normal | 일반적인 배송 조건 |
| 급행 배송 | Express | 일반 배송보다 긴급도가 높은 배송 |

배송 타입은 확률 기반으로 무작위 배정한다.

정적 물류와 동적 물류는 동일한 타입 생성 확률을 적용한다.

배송 타입은 현재 마일스톤에서 배송 긴급도와 경제적 가치의 차이를 표현하는 용도로 사용한다.

파손 주의, 대형 화물 등 별도의 운송 규칙을 요구하는 배송 타입은 현재 범위에서 제외한다.

### 배송 타입 설정

배송 타입별로 다음 값을 설정 데이터에서 관리한다.

- 생성 확률
- 배송 제한 시간 계수
- 시간 초과 손실 계수
- 배송 실패 페널티 계수
- 기타 타입별 밸런싱 값

배송 타입 식별자와 수치 설정을 분리한다. 타입별 수치를 Enum에 직접 포함하지 않는다.

# 7. 배송 제한 시간 시스템

## 7.1. 제한 시간 산정

각 물류의 배송 제한 시간은 물류 생성 시점에 결정한다.

기본 산식은 다음과 같다.

`T_limit = T_base(D) * M_type + R`

| 변수 | 설명 |
|---|---|
| T_limit | 최종 배송 제한 시간 |
| T_base(D) | 배송 거리 기반 기본 제한 시간 |
| D | 물류센터와 배송지 사이의 거리 |
| M_type | 배송 타입별 제한 시간 계수 |
| R | 무작위 시간 편차 |

### 거리 계산

배송 거리는 물류센터와 배송지 사이의 직선거리를 기준으로 한다.

- Euclidean Distance 사용
- Unity 구현에서는 XZ 평면의 2D 거리를 사용
- 실제 주행 거리 및 도로 경로는 고려하지 않음

### 무작위 편차

배송 제한 시간에는 무작위 편차를 적용한다.

구체적인 최소·최대 편차와 분포 방식은 밸런싱 단계에서 결정한다.

## 7.2. 제한 시간 감소

- 물류가 생성되는 시점부터 배송 제한 시간이 감소한다.
- 플레이어가 물류를 확인하거나 상차하는 시점과 관계없이 시간이 흐른다.
- 상차 및 하차 중에도 제한 시간이 감소한다.
- 모든 물류는 동일한 게임 시간 시스템을 기준으로 제한 시간을 관리한다.

동일 배송지 그룹의 물류는 같은 시간 시스템을 사용하므로 남은 제한 시간에 따른 상대적인 우선순위는 유지된다.

## 7.3. 제한 시간 초과

배송 제한 시간을 초과하더라도 배송 자체가 실패하는 것은 아니다.

- 제한 시간 내 배송 완료: 기본 보상과 추가 보상 지급
- 제한 시간 초과 후 배송 완료: 기본 보상 지급, 시간 추가 보상 미지급, 시간 초과 손실 적용
- 하루 종료까지 미배송: 배송 실패 처리 및 배송 실패 페널티 적용

시간 초과 손실은 물류의 제한 시간이 최초로 초과되는 시점에 한 번만 적용한다.

시간이 계속 초과되어도 손실 금액이 누적되지는 않는다.

### 시간 초과 손실 산식

`L_late = L * M_late,type`

| 변수 | 설명 |
|---|---|
| L_late | 해당 물류의 시간 초과 손실 |
| L | 일반 물류 기준 시간 초과 손실 |
| M_late,type | 배송 타입별 시간 초과 손실 계수 |

시간 초과 손실과 배송 실패 페널티는 서로 다른 항목으로 관리한다.

## 7.4. 배송 우선순위

같은 배송지에 할당된 여러 물류는 남은 배송 제한 시간이 짧은 순서대로 처리한다.

- 물류센터에서 그룹 상차 시 동일한 우선순위 적용
- 배송지에서 그룹 하차 시 동일한 우선순위 적용
- 남은 제한 시간이 짧은 물류부터 처리

# 8. 물류센터 및 상차 시스템

## 8.1. 물류센터 UI

플레이어가 물류센터에 접근하여 상호작용 키를 일정 시간 유지하면 물류센터 UI를 표시한다.

UI를 여는 데 걸리는 시간은 물류센터 설정값이며 구체적인 값은 밸런싱 단계에서 결정한다.

UI에서는 배송지별 물류 그룹을 확인하고 상차할 물류를 선택할 수 있다.

### 그룹 정렬

배송지 그룹은 물류센터와 배송지 사이의 거리순으로 정렬한다.

모든 배송지 그룹은 목록에 표시한다. 해당 배송지에 미적재 물류가 없어도 그룹은 사라지지 않는다.

그룹에 속한 물류는 그룹 하위임을 알 수 있도록 왼쪽에 여백을 두고 표시한다.

### 그룹 내부 표시

각 배송지 그룹에 포함된 개별 물류의 배송 제한 시간을 프로그레스 바로 표시한다.

그룹 내부 물류는 남은 배송 제한 시간이 짧은 순서대로 정렬한다.

현재 차량에 적재된 물류 수량을 배송지별로 확인할 수 있다.

미적재 물류의 수량을 차량 적재량 정보와 혼합하여 표시하지 않는다.

## 8.2. 상차 선택 방식

플레이어는 다음 두 가지 방식으로 상차할 물류를 선택할 수 있다.

1. 개별 물류 선택
2. 배송지 그룹 전체 선택

그룹을 선택하면 해당 그룹에 속한 물류를 남은 배송 제한 시간이 짧은 순서대로 상차한다.

물류를 선택하지 않고 상호작용 키를 유지하면 상차 대기열 선두 물류부터 상차한다.

선택한 그룹을 모두 상차하면 상차를 멈추고, 다른 그룹 물류를 자동으로 이어서 상차하지 않는다.

### UI 조작

물류센터 UI는 마우스로 조작한다. UI가 열려 있는 동안 커서가 표시된다.

물류 또는 배송지 그룹을 마우스로 누르고 있는 동안 상차가 진행된다. 물류 한 개당 소요시간이 필요하며, 그룹을 누르고 있으면 그룹 내 물류를 남은 제한 시간이 짧은 순서대로 이어서 상차한다.

상차 진행도는 현재 물류 하나의 진행 바로 표시하고, 상차가 완료된 물류의 행은 목록에서 하나씩 사라진다. 배송지 그룹의 미적재 수량과 적재 수량은 완료 즉시 갱신되며, 그룹 머리글은 물류가 모두 실린 뒤에도 `x0` 상태로 목록에 남는다.

각 물류의 배송 제한 시간은 생성 시점에 확정된 만료 시각을 게임 시계 기준(`HH:mm`)으로 표시한다. 제한 시간 프로그레스 바는 남은 제한 시간의 비율을 실시간으로 보여 준다.

누르고 있던 마우스를 놓거나 커서가 해당 행을 벗어나면 진행 중인 물류의 상차 진행도를 초기화한다. 이미 상차가 완료된 물류는 차량에 유지한다.

고른 물류를 모두 상차하면 마우스를 계속 누르고 있더라도 해당 상호작용을 종료한다.

상차가 진행되는 동안에도 UI는 닫히지 않는다. 플레이어가 닫기 버튼을 누르면 UI가 닫히고 진행 중인 상차는 취소된다.

## 8.3. 상차 진행

- 상차할 물류를 선택한 뒤 상호작용 키를 누르고 있으면 상차가 진행된다.
- 물류 한 개당 설정된 상차 소요시간이 필요하다.
- 현재 상차 중인 물류 하나의 진행 UI를 표시한다.
- 상차가 완료되면 다음 물류로 넘어간다.
- 전체 그룹 작업시간을 하나의 긴 프로그레스 바로 표현하지 않는다.

상차 소요시간은 물류별 N초이며 구체적인 값은 밸런싱 단계에서 결정한다.

## 8.4. 상차 중단

상차 중 상호작용 키를 놓으면 현재 진행 중인 물류의 상차 진행도를 초기화한다.

- 이미 상차 완료된 물류: 차량에 유지
- 현재 상차 중인 물류: 진행도 초기화
- 아직 상차를 시작하지 않은 물류: 물류센터에 유지

이후 다시 상차를 시작하면 미완료 물류부터 진행한다.

## 8.5. 적재 한도

차량은 물류 개수 기반의 적재 한도를 가진다.

- 모든 물류는 동일한 적재 단위로 취급한다.
- 무게 및 부피에 따른 차이는 구현하지 않는다.
- 차량 적재 한도를 초과하여 물류를 상차할 수 없다.
- 그룹 상차 도중 적재 한도에 도달하면 상차를 자동 종료한다.
- 적재하지 못한 나머지 물류는 물류센터에 남는다.

## 8.6. 상차 비용

현재 마일스톤에서는 상차 비용을 부과하지 않는다.

개별 상차, 그룹 상차, 물류센터 재방문 상차 모두 무료이다.

# 9. 운송 및 배송 시스템

## 9.1. 배송 경로

플레이어는 정해진 배송 순서 없이 배송지를 자유롭게 방문할 수 있다.

- 배송 순서는 플레이어가 직접 결정한다.
- 여러 배송지를 원하는 순서로 방문할 수 있다.
- 배송 도중 물류센터에 재방문하여 추가 물류를 상차할 수 있다.
- 배송 제한 시간과 차량 적재량을 고려하여 배송 계획을 수립한다.

현재 마일스톤에서는 지도 및 미니맵 기능을 후순위로 둔다.

맵의 규모가 크지 않고 별도 개발 비용이 발생하기 때문에 현재 핵심 기능으로 구현하지 않는다.

## 9.2. 배송지 도착 및 하차

플레이어가 배송지에 접근하여 상호작용 키로 상호작용하면 해당 배송지에 배송할 물류를 하차할 수 있다.

- 차량에 해당 배송지로 배송할 물류가 하나 이상 있어야 한다.
- 배송할 물류가 없다면 상호작용할 수 없다.
- 물류 한 개당 설정된 하차 소요시간이 필요하다.
- 상호작용 키를 누르고 있는 동안 하차가 진행된다.

하차 소요시간은 물류별 N초이며 구체적인 값은 밸런싱 단계에서 결정한다.

## 9.3. 하차 우선순위

동일 배송지에 할당된 여러 물류는 남은 배송 제한 시간이 짧은 순서대로 하차한다.

## 9.4. 하차 중단

하차 중 상호작용 키를 놓으면 현재 진행 중인 물류의 하차 진행도를 초기화한다.

- 이미 하차 완료된 물류: 배송 완료 상태 유지
- 현재 하차 중인 물류: 진행도 초기화
- 아직 하차를 시작하지 않은 물류: 차량에 유지

배송 완료 판정은 개별 물류의 실제 하차 완료 시점에 이루어진다.

# 10. 차량 및 환경 시스템

## 10.1. 플레이어 차량

현재 마일스톤에서는 단일 플레이어블 차량을 사용한다.

- 차량 종류: 1종
- 차량 성능: 주행 모드에 따라 달라짐(10.4)
- 적재 한도: 고정

차량 성능 업그레이드 및 차량 종류별 성능 차이는 현재 마일스톤에서 구현하지 않는다.

## 10.2. 충돌 처리

차량 충돌은 단순한 물리적 방해 요소로만 작동한다.

충돌로 인해 다음과 같은 추가 페널티는 발생하지 않는다.

- 별도의 속도 저하 디버프
- 물류 파손
- 배송 보상 감소
- 경제적 페널티

### 이동 및 충돌 구현 기준

차량은 물리 바디를 사용하되, 지면 판정과 서스펜션은 바퀴 4점의 스피어캐스트로 처리하고 구동·조향·횡방향 접지는 힘으로 인가한다. 지면은 별도 레이어(`Drivable`)로 판정한다.

맵의 충돌 메시는 타일 이음매에서 생기는 물리 충격을 막기 위해 하나의 메시로 베이크한다. 이는 조작감 확보를 위한 구현 기준이며, 충돌이 페널티를 만들지 않는다는 10.2의 규칙은 동일하다.

## 10.3. 환경 장애물

현재 마일스톤에서는 고정 장애물만 구현한다.

- 장애물은 맵 제작 단계에서 고정 배치한다.
- 매 플레이마다 동일한 위치에 배치한다.
- 보행자 및 NPC 차량 등 이동 장애물은 구현하지 않는다.
- 별도의 상호작용 장애물은 구현하지 않는다.

배송지도 맵 제작 단계에서 고정 배치한다.

따라서 장애물과 배송지는 게임 시작 시 무작위 생성하거나 배치하지 않는다.

### 맵 구성 및 축척

1차 맵은 3×3 블록 도로 루프에 배송지 5곳과 물류센터 1곳을 배치하고, 장애물과 가로 시설물을 같은 블록 안에 고정 배치한다.

축척 기준은 도로 1칸 3m(2차선), 플레이어 차량 폭 0.38m·길이 0.81m이다. 맵 제작 도구(맵 페인터)의 기본 칸 크기도 3m를 사용한다.

## 10.4. 주행 모드와 드리프트

### 주행 모드

플레이어는 ctrl 키로 주행 모드를 전환한다.

| 모드 | 용도 | 성능 |
|---|---|---|
| 일반 | 도시 주행, 좁은 구간에서의 정밀한 조작 | 기준 성능 |
| 고속 | 배송 제한 시간 대응, 추격자 회피(후속) | 높은 최고 속도, 낮은 회전 성능·접지력 |

- 두 모드의 차이는 최고 속도, 가속도, 최대 회전 속도, 접지력, 조향 반응 속도로 구성한다.
- 모드 전환 시 성능 값은 설정된 전환 시간에 걸쳐 보간한다. 회전 성능이 계단처럼 튀지 않게 하기 위함이다.
- 전환은 접지 상태이며 상호작용 중이 아닐 때만 허용한다.
- 모드 전환에는 비용(연료·내구도 등)을 두지 않는다.
- 고속 모드는 같은 속도에서의 최소 회전 반경이 일반 모드보다 항상 크다. 따라서 좁은 구간에서는 감속만으로 해결되지 않고 모드 전환이 필요하다.
- 고속 모드에서 일반 모드로 전환해도 관성은 유지되며, 최고 속도에 가속도 기준으로 자연 감속한다.
- 현재 주행 모드는 HUD에 표시한다.

### 드리프트

- shift 키를 누르고 있는 동안 드리프트가 발생한다.
- 접지 상태이고 전진 속도가 설정값 이상일 때만 발동한다.
- 드리프트 중에는 접지력이 크게 낮아지고 최대 회전 속도가 높아진다.
- 별도의 속도 감소 로직을 두지 않는다. 옆방향 미끄러짐이 감쇠되는 과정에서 속도가 자연히 줄어든다.
- 키를 놓으면 접지력이 즉시 원래 값으로 돌아온다.
- 드리프트는 배송 제한 시간, 충돌 규칙, 보상에 영향을 주지 않는다.

주행 모드와 드리프트에 관련된 구체적인 수치는 밸런싱 단계에서 결정한다(16.4).

## 10.5. 카메라

플레이어 차량을 뒤에서 따라가는 3인칭 추적 카메라를 사용한다.

- 카메라와 차량 사이에 벽·건물 등의 장애물이 있으면 카메라를 차량 쪽으로 당겨 벽을 뚫지 않는다.
- 카메라를 당길 때 높이는 유지하고, 차량에 지나치게 붙지 않도록 최소 거리를 둔다.
- 장애물에 닿을 때 화면이 순간적으로 확대되는 연출은 사용하지 않는다.
- 목적지 방향은 화면 상단 나침반(13장)으로 보조한다.

# 11. 보상 및 경제 시스템

## 11.1. 기본 보상 구조

배송 보상은 기본 배송료, 거리 추가 배송료, 시간 추가 보상으로 구성한다.

### 기본 배송료

- 모든 정상 배송에 적용한다.
- 물류별 기본 배송료를 지급한다.
- 보상 최저 하한으로 작동한다.

### 거리 추가 배송료

- 물류센터와 배송지 사이의 거리를 기준으로 산정한다.
- 실제 주행 거리가 아닌 직선거리를 기준으로 한다.

### 시간 추가 보상

- 배송 제한 시간 내에 물류 배송을 완료하면 지급한다.
- 배송 제한 시간 초과 후 배송을 완료하면 지급하지 않는다.

각 보상의 구체적인 금액 및 산식은 밸런싱 단계에서 결정한다.

## 11.2. 제한 시간 내 배송 완료

배송 제한 시간 내 배송을 완료하면 기본 배송료와 시간 추가 보상을 지급한다.

거리 추가 배송료는 배송을 완료하면 지급한다(2026-11-11 확정, 16.1-5).

## 11.3. 제한 시간 초과 후 배송 완료

배송 제한 시간을 초과한 뒤에도 배송을 완료하면 다음 규칙을 적용한다.

- 기본 배송료 지급
- 시간 추가 보상 미지급
- 시간 초과 손실 적용
- 배송 자체는 성공으로 판정

## 11.4. 하루 종료 시 미배송

영업 종료 시각까지 배송을 완료하지 못한 물류는 배송 실패 처리한다.

- 기본 배송료 미지급
- 추가 배송 보상 미지급
- 배송 실패 페널티 적용
- 미배송 물류 폐기

배송 실패 페널티는 일반 물류의 기준 손실값을 바탕으로 배송 타입별 계수를 적용한다.

`P_failure = P * M_type`

| 변수 | 설명 |
|---|---|
| P_failure | 최종 배송 실패 페널티 |
| P | 일반 물류 기준 배송 실패 손실 |
| M_type | 배송 타입별 실패 페널티 계수 |

## 11.5. 경제 시스템 범위

현재 마일스톤에서는 수익 사용처를 구현하지 않는다.

차량 및 물류센터 업그레이드, 성능 개선 등 성장 시스템은 후속 마일스톤에서 다룬다.

# 12. 일일 정산 시스템

## 12.1. 정산 진입

다음 중 하나가 발생하면 하루 운영을 종료하고 일일 정산 화면으로 전환한다.

- 영업 종료 시각 도달
- 모든 배송 완료에 따른 조기 종료

영업 종료 시 미배송 물류는 일괄 배송 실패 처리한다.

## 12.2. 정산 화면 구성

정산 화면은 요약과 상세 내역을 하나의 화면에 통합한다.

### 상단 요약

- 최종 정산 금액
- 배송 완료 건수
- 미배송 건수
- 미배송 페널티

### 하단 상세 내역

- 기본 배송료 합계
- 거리 추가 배송료 합계
- 시간 추가 보상 획득액
- 시간 추가 보상 미지급액
- 시간 초과 손실
- 미배송 페널티

화면에는 해당 하루의 총 수익과 손실을 이해할 수 있도록 항목별 합계를 표시한다.

정산 이후 메인 화면으로 이동한다.

## 12.3. 정산 계산

기본적인 정산 구조는 다음과 같다.

`FinalSettlement = DeliveryIncome - DeliveryFailurePenalty - LateDeliveryLoss`

여기서 `DeliveryIncome`은 실제 지급 대상이 되는 배송 보상의 합계이다.

거리 추가 배송료는 배송 완료 시 지급하며, 미배송 페널티와 시간 초과 손실은 중복 적용하지 않는다. 최종 정산 금액은 음수를 허용하고 하한을 두지 않는다(2026-11-11 확정, 16.1-4~6).

# 16. 미결정 사항 및 추가 검토 사항

아래 항목은 현재 논의에서 구체적으로 확정되지 않은 사항이다. 임의의 값이나 규칙을 적용하지 않고 별도 관리한다.

## 16.1. 우선 확정이 필요한 정책

### 1. 모든 배송 완료의 정확한 판정 기준

하루 조기 종료 조건은 모든 배송 완료로 확정되었다.

다만 다음 상황의 정확한 처리 기준은 추가 확인이 필요하다.

- 현재 생성된 물류를 모두 배송했지만, 앞으로 생성될 동적 물류가 남아 있는 경우
- 동적 물류 생성 시스템이 종료되었고 현재 존재하는 물류를 모두 배송한 경우
- 동적 물류 생성 가능량을 모두 소진했지만 아직 예정된 생성 시점이 남아 있는 경우

조기 종료를 판정할 때 '모든 배송'이 현재 생성된 물류 전체를 의미하는지, 하루 동안 생성될 예정인 물류까지 포함하는지 정의해야 한다.

**확정(2026-11-11):** 동적 물류 생성이 끝난 상태(생성 마감 도달·생성 가능량 소진·할당 가능 배송지 없음)에서 배송되지 않은 물류가 하나도 없을 때만 조기 종료한다. 앞으로 생성될 동적 물류가 남아 있으면 영업을 계속한다.

### 2. 정적 물류 생성량이 배송지 할당 가능량을 초과하는 경우

**확정(2026-11-11):** 정적 물류 생성량을 배송지 전체 잔여 할당량으로 제한한다(4.1에 반영). 무작위로 결정한 생성량이 잔여 할당량보다 크면 잔여 할당량만큼만 생성하며, 생성한 물류를 폐기하지 않는다.

### 3. 동적 물류 생성 실패 시 생성 가능량 처리

**확정(2026-11-11):** 하루 생성 가능량은 생성 성공 기준으로 차감한다(4.2에 반영). 할당 가능한 배송지가 없어 생성에 실패하면 생성 시스템 자체가 종료되므로 이후 차감은 발생하지 않는다.

### 4. 시간 초과 손실과 배송 실패 페널티의 중복 적용

배송 제한 시간이 초과된 물류가 영업 종료까지 배송되지 않은 경우 다음 두 손실이 함께 적용되는지 확정이 필요하다.

- 시간 초과 손실
- 배송 실패 페널티

두 항목은 별도 손실로 구분하기로 했으나, 하나의 미배송 물류에 두 손실을 중복 적용할지는 명시되지 않았다.

**확정(2026-11-11):** 중복 적용하지 않는다. 시간 초과 손실은 배송을 완료한 물류에만, 배송 실패 페널티는 영업 종료까지 배송하지 못한 물류에만 적용한다.

### 5. 거리 추가 배송료 지급 조건

거리 추가 배송료는 배송 거리 기반 보상으로 결정되었지만 다음 조건은 확정이 필요하다.

- 제한 시간 내 배송 완료 시 지급 여부
- 제한 시간 초과 후 배송 완료 시 지급 여부
- 하루 종료 시 미배송인 경우 미지급 여부

권장 구조는 실제 배송 완료 시 지급하고 미배송 시 지급하지 않는 방식이다. 다만 이는 아직 확정된 규칙이 아니다.

**확정(2026-11-11):** 배송을 완료하면 제한 시간 내·초과 여부와 무관하게 지급하고, 미배송이면 지급하지 않는다.

### 6. 영업 종료 시 최종 정산의 세부 계산

다음 항목의 계산 기준을 추가로 확정해야 한다.

- 미배송 페널티와 시간 초과 손실의 중복 적용
- 최종 정산 금액의 최저값 제한 여부
- 정산 결과가 음수가 될 수 있는지
- 시간 초과 보상 미지급액의 표시 및 계산 기준

**확정(2026-11-11):** 미배송 페널티와 시간 초과 손실은 중복 적용하지 않는다(4번). 최종 정산 금액은 음수를 허용하고 하한을 두지 않는다. 시간 추가 보상 미지급액은 정산 화면에 별도 항목으로 표시하되 최종 금액에서 다시 차감하지 않는다(지급 대상에서 제외된 금액이므로).

## 16.2. 상호작용 및 작업 처리 정책

아래 6개 항목은 2026-11-11에 모두 확정되었다. 항목 번호는 개발 계획 4장의 참조를 위해 유지한다.

### 1. 상차 및 하차 중 차량 이동 가능 여부

**확정(2026-11-11):** 작업 중에도 차량을 조작할 수 있다. 이동해 상호작용 범위를 벗어나면 3번 규칙에 따라 자동 중단된다. 드리프트와 주행 모드 전환은 작업 중 차단한다.

### 2. 상차 및 하차 중 다른 UI 호출 가능 여부

**확정(2026-11-11):** 호출할 수 없다. 작업 중에는 물류센터 UI 재호출과 그 밖의 메뉴 호출을 막으며, ESC(게임 종료)만 예외로 둔다.

### 3. 작업 도중 상호작용 범위를 벗어났을 때의 처리

**확정(2026-11-11):** 자동 중단하고 현재 물류의 진행도를 초기화한다(8.4, 9.4와 동일한 규칙). 이미 완료된 물류는 유지한다.

### 4. 작업 도중 다른 상호작용 대상으로 이동했을 때의 처리

**확정(2026-11-11):** 진행 중인 작업을 중단하고 새 대상을 즉시 작업 대상으로 삼는다. 상호작용 키를 누르고 있으면 새 대상의 작업이 바로 시작된다.

### 5. 차량 적재 한도 도달 시 남은 그룹 물류 수량 표시

**확정(2026-11-11):** 그룹 목록은 유지하고 적재 불가 상태(비활성)로 표시한다. 남은 물류 수량은 차량 적재량과 분리해 표시한다(8.1).

### 6. 배송지에 도착했지만 배송할 물류가 없는 경우의 피드백

**확정(2026-11-11):** 기본적으로 아무 표시도 하지 않는다. 다만 해당 배송지에서 상호작용 키를 누르면 '배송할 물류 없음'을 표시한다.

## 16.3. 시간 시스템 세부 정책

다음 값과 동작은 확정되지 않았다.

- 현실 시간 대비 게임 시간 배속
- 물류센터 UI를 열어둔 상태에서 시간 진행 여부
- 기타 UI 사용 중 시간 진행 여부
- 게임 시간의 최소 단위 및 표시 갱신 주기
- 시간과 동적 물류 생성 시각이 정확히 일치할 때의 이벤트 처리 순서

상차·하차 중에는 게임 시간이 진행된다는 규칙은 확정되어 있다.

**확정(2026-11-11):** 물류센터 상차 UI를 열어 둔 동안에도 게임 시간과 물류 제한 시간이 계속 진행된다. UI가 열린 상태에서 영업 종료 시각에 도달하면 UI를 닫고 하루 운영을 종료한다.

# 17. 기획 확정 사항 요약

현재 마일스톤의 핵심 규칙을 요약하면 다음과 같다.

1. 플레이어는 차량을 직접 조작하여 물류센터에서 물류를 상차하고 배송지에 운송한다.
2. 하루 운영은 기본 09:00부터 18:00까지 진행한다.
3. 정적 물류는 하루 시작 시 모두 생성한 뒤 플레이를 시작한다.
4. 동적 물류는 하루 중 무작위 시점에 생성하며, 실제 생성 시점을 기준으로 다음 생성 간격을 결정한다.
5. 동적 물류는 영업 종료 2시간 전에 생성을 중단한다.
6. 동적 물류 생성 마감 이후에도 기존 물류의 상차와 배송은 가능하다.
7. 모든 물류는 생성 즉시 배송 제한 시간이 감소하기 시작한다.
8. 배송 제한 시간은 물류센터와 배송지 사이의 직선거리 및 배송 타입에 따라 결정한다.
9. 배송지별 할당량은 하루 누적 기준이며, 배송 완료 후에도 복구되지 않는다.
10. 모든 배송지의 할당 한도 소진은 신규 할당을 제한할 뿐 하루 종료를 발생시키지 않는다.
11. 동적 물류 생성 시 할당 가능한 배송지가 없다면 동적 물류 생성 시스템을 종료한다.
12. 플레이어는 배송 순서를 자유롭게 결정하며, 중간에 물류센터에 복귀하여 추가 상차할 수 있다.
13. 상차와 하차는 물류별로 진행하며 상호작용 키를 유지해야 한다.
14. 상차 및 하차 중단 시 현재 작업 중인 물류의 진행도만 초기화하고 완료된 물류는 유지한다.
15. 배송 제한 시간 초과는 배송 실패가 아니며, 추가 보상 미지급 및 시간 초과 손실을 발생시킨다.
16. 영업 종료 시 미배송 물류는 폐기하고 배송 실패 페널티를 적용한다.
17. 모든 배송이 완료되면 하루 운영을 조기 종료한다.
18. 영업 종료 시에는 작업 도중이라도 즉시 운영을 중단하고 일일 정산으로 전환한다.
19. 현재 마일스톤에서는 단일 차량, 고정 장애물, 고정 배송지를 사용한다.
20. 차량 및 물류센터 성장 시스템, 경찰 추격 시스템, 이동 장애물 등은 후속 개발 범위로 둔다.
21. 플레이어는 ctrl 키로 일반·고속 주행 모드를 전환하며, 두 모드는 최고 속도와 핸들링에서 차이가 난다.
22. shift 키 드리프트는 접지력과 회전 성능만 바꾸며, 별도 자원이나 페널티를 발생시키지 않는다.
23. 카메라는 차량을 뒤에서 따라가며, 장애물이 시야를 가리면 높이를 유지한 채 차량 쪽으로 당겨져 벽을 뚫지 않는다.
24. 1차 맵은 3×3 블록 도로 루프에 배송지 5곳·물류센터 1곳을 두고, 도로 1칸 2.25m 축척을 기준으로 제작한다.
