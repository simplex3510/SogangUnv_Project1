## 세션 운영 방법

### 새 세션 시작 시
1. 이 문서의 "현재 진행 상태"와 "5. 진행 기록"에서 마지막 작업을 확인합니다.
2. 해당 단계의 "선행 결정"이 미확정이면 사용자와 먼저 확정합니다.
3. 착수할 파일 목록을 사용자에게 제시하고 승인을 받은 뒤 구현합니다.

### 작업 완료 시 (이 문서를 반드시 갱신)
1. 해당 단계의 체크박스(`[ ]` → `[x]`)를 갱신합니다.
2. "현재 진행 상태"의 단계 표기를 갱신합니다.
3. "4. 선행 결정 목록"에서 확정된 결정에 요약을 적습니다.
4. "5. 진행 기록"에 날짜·작업 내용·결과·다음 작업을 한 줄 추가합니다.
5. 최종 갱신일을 고칩니다.

## 1. 마일스톤 완료 정의

아래 조건을 모두 만족하면 현재 마일스톤 완료로 판정합니다.

- 하루 운영 09:00 → 18:00 사이클이 처음부터 끝까지 동작한다.
- 정적·동적 물류가 기획 규칙대로 생성·할당·제한 시간 관리된다.
- 상차/하차가 물류 개별 단위로 진행되며, 중단·재개 규칙이 지켜진다.
- 배송 완료 시 보상이, 영업 종료 시 실패 페널티가 계산된다.
- 일일 정산 화면이 표시되고 메인 화면으로 전환된다.

다음은 이번 마일스톤에서 제외합니다(기획서 15장): 경찰 추격, 이동 장애물, 차량/물류센터 업그레이드, 수익 사용처, 미니맵, 다음 날 운영, 물류 이월, 시간 배속 조정, 일시정지.

## 3. 개발 순서

각 단계는 단독으로 컴파일·Play 검증이 가능하도록 잘랐습니다. 단계 번호는 이 문서가 기준입니다.

### 1단계 — 데이터·설정 기반 `[x]`
- **목표:** 기획서 6장의 물류 데이터를 실제 데이터로 만들고, 배송 타입과 설정 SO 골격을 마련한다.
- **작업 항목**
  - [x] `Parcel`을 순수 데이터 클래스로 전환: 식별자, 배송지, 배송 타입, 생성 시각, 제한 시간, 남은 시간, 진행 상태, 보상 스냅샷(생성 시점 값 고정 원칙)
  - [x] `DeliveryType` enum(Normal/Express) 추가 — 타입 수치는 enum에 넣지 않음
  - [x] `DeliveryTypeConfig` SO 골격(타입별 확률·계수)
  - [x] 설정 SO는 이 단계에서 필요한 것만 생성하고, 나머지는 사용 단계에서 추가
- **선행 결정:** 없음
- **예상 변경 파일(제안):** `Parcel.cs`, 신규 `DeliveryType.cs`, 신규 설정 SO 클래스·에셋

## 6. 참고 사항 (세션이 알아야 할 설계 방향)

- 게임 시간은 `Time.timeScale`과 분리된 자체 시계를 사용한다. 물리·조작은 실시간 기준을 유지한다.
- 물류 생성 시점에 제한 시간·보상 관련 값을 물류 데이터에 스냅샷으로 저장한다(기획서 6.1). 이후 설정 변경은 이미 생성된 물류에 영향을 주지 않는다.
- 설정 SO는 필요한 단계에서 필요한 것만 추가한다(과설계 방지).
- 차량 주행 성능과 드리프트 수치는 `Assets/Game/Configs/VehicleConfig.asset`에서 조정한다. 컴포넌트가 아닌 이 자산에 모든 모드 값이 있으므로, 튜닝도 이 자산에서 한다.
- 시스템 책임 구분은 기획서 14.1의 명칭을 따른다.
- 밸런싱 수치는 Editor 조정 가능한 설정 데이터로 관리하고, 확정 전 값은 `// TODO(tuning)`으로 표시한다.
- 상호작용 입력은 기존 `InteractableObject`의 상호작용 키 유지 + 1회 소요시간 모델을 유지·확장한다. `_interactionDuration`은 이제 "물류 1개당 소요시간"(상차·하차 각 1초)이고, 물류센터 UI를 여는 시간은 `LogisticsCenter._uiOpenDuration`(기본 1초)으로 따로 조정한다.
- 게임 중 커서는 `GameManager`가 숨기고 잠근다. 상차 UI가 열려 있는 동안만 커서를 표시하고 잠금을 풀며, 닫히면 원래대로 되돌린다.
- 비율로 채우는 `Image`는 스프라이트가 없으면 `Filled` 타입이 무시되어 꽉 찬 사각형으로 그려진다. 진행 바는 빌트인 `UISprite`(`UI/Skin/UISprite.psd`)를 사용한다.
- 상차 UI는 화면 캔버스(`/Canvas`) 아래 `LogisticsPanel`·`InteractionProgress`·`MessageText`로 구성했고, `/LogisticsCenter/Canvas`는 사용하지 않는다(정리 후보).
- TMP 기본 폰트(LiberationSans)에 한글 글리프가 없어 새 UI 문구는 영문으로 표시한다. 한글 폰트 에셋을 추가하면 문구를 교체한다.
- 상차 UI에서 아무것도 선택하지 않고 상호작용 키를 유지하면 대기열 선두부터 상차한다(선택 UI를 거치지 않는 간편 경로). UI에서 그룹·개별 물류를 고른 경우에는 그 선택만 상차하고, 다 실으면 다른 그룹으로 넘어가지 않는다. 선택이 남아 있으면 키를 다시 눌러도 UI를 다시 열지 않고 바로 상차를 시작한다.
- 보상·손실 금액은 물류 생성 시점에 `RewardSystem.CreateReward`가 계산해 `Parcel.Reward` 스냅샷에 고정한다. 정산은 이 스냅샷만 더하므로 설정을 바꿔도 이미 생성된 물류의 금액은 변하지 않는다.
- 정산은 `SettlementSystem.FinalizeDay()`가 확정하고, 하루 종료 판정은 `DailyOperationSystem`이 맡는다. 영업 종료 시각 도달과 조기 종료(동적 생성 종료 + 미배송 0) 모두 `EndDay`를 거치며, `EndDay`가 조작 잠금 → 동적 생성 중단 → 미배송 실패 처리·정산 순서로 진행한다.
- 하루 종료 시 `PlayerMovementController.SetControlEnabled(false)`가 입력을 끊고 속도를 0으로 만들며, `PlayerInteractionController.SetControlEnabled(false)`가 진행 중인 상차·하차와 열려 있는 상차 UI를 닫는다. 조작 잠금은 `DailyOperationSystem`만 호출한다.
